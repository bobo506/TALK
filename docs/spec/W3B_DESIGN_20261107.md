## 二、数据模型与路径安全

data_root 是可信 TALK 部署数据根，project_root 是 DB 登记并核实的源码 cwd；两者不能默认相等。P、M 分别由现有 server/workspace_paths.py:20-37 的 project_component 和 member_component 精确编码，复用其 role_dir 和路径检查，不造第二套编码。建议添加纯派生函数，固定新布局：

    workspaces/P/roles/M/profiles/            W3a 已有身份档
    workspaces/P/roles/M/native-home/         HOME；内含 .codex、.kimi-code、.dsh、.codebuddy
    workspaces/P/roles/M/sessions/execution-session-store.sqlite3  包括 WAL/SHM
    workspaces/P/roles/M/state/records/       角色 ownership
    workspaces/P/roles/M/state/control/       角色 launch 控制文件
    workspaces/P/roles/M/state/manager/<runner>/  health 与 drain
    workspaces/P/roles/M/logs/                该角色诊断及可选子进程输出

launch 文件名用校验过的 UUID 或无碰撞编码。项目级 API/总控状态和汇总日志可保留原根，不能宣称已是角色隔离；角色日志继续脱敏并保持保留策略。不同角色分别拥有 HOME、原生 session 和 TALK store；禁止拷贝历史登录态。layout 只能取权威 DB 角色记录，缺失、冲突、未知布局或读取失败拒绝；原纯历史名册无 project_roles 行时只按现有 legacy 合同行为处理，不按文件存在性回退。

Windows 需复用 workspace_paths 的逐祖先 lstat、大小写规范、边界和 reparse 拒绝；每次创建、打开、发布和恢复均重核路径链、文件类型、私有 ACL 和对象身份。新路径不得使用会碰撞的 sanitize，长组件拒绝而不截断。使用无跟随句柄或等价身份校验对抗检查后 junction 替换，无法证明安全则拒绝开放；当前 resolver 明确不能独自消除并发替换。共同 cwd 不构成源码访问沙箱。

## 三、Key、启动、停止及恢复

git 新布局继续使用 key_path(data_root, project, member, git_key_root=可信外部根)，直接消费 W3a 已生成的编码名；非 git 仅允许 data_root/keys/P/M.key 精确子树。legacy 保持旧 key_file_path 和既有显式覆盖优先级。两名同时存在仍仅用当前布局路径，缺失不跨布局回退。形态未知、形态或根发生变化、身份不匹配、路径和权限不安全均拒绝；operator Key 守卫不放宽。非 git 的精确子树例外仅限新布局，不能把所有 legacy 的单 key_root 改成内部路径。

运行时基于权威布局和成员归属构造一次可信角色上下文，包括 data_root、project_root、project/member、layout、key、HOME、session、state、logs、runner；生成、worker、runtime spec、身份检查、host preflight、profile fingerprint、DSH patch 和 recovery 均使用该合同。工作区角色的显式 Key/HOME/session 覆盖值若不等于可信派生值则拒绝。静态 hosts 初版继续拒绝新布局，直至具备等价作用域校验；legacy 自定义配置不改变。还须核查删除和凭据恢复消费者，例如 scripts/role_delete.py:153；超白名单须补授权。

在服务端事务内统一对 single start、start-all、startup、首次配置等所有入队路径按 project+member 查 layout。在隔离能力可靠开放之前，新布局必须返回 workspace_runtime_not_ready，客户端 guard 缺省或 false 不得放行；自动 startup 在冷恢复之前拒绝（现有 server/role_startup.py:217-220）。批量逐项报告 skipped；legacy 合同不变；stop 不受启动门阻碍。已有新布局 pending 意图不得静默执行或删除，须按既有授权及状态协议处理。

建议可信部署级能力门默认关闭，客户端输入不能开启；必须证明服务端、runtime、manager 版本与实例绑定且旧 manager 不能领取新角色，未知或混版本关闭。数据库单字段或客户端自报不足以证明。片 1、2 保持关闭，片 3 证据满足后再启用；若无法证明继续拒绝。stop/recovery 复用 project/member、generation、launch、instance、owner、human 授权和进程证明，只作用于目标 control 和原宿主持有 Popen；PID 或路径存在不足以证明所有权。恢复选择该布局唯一 health，校验项目成员和对象身份并重核 CAS；缺证据拒绝。运行器负责原生子进程生命周期。按工作区 stop 不等于整机 runtime shutdown。

## 四、遗留、风险和验收

单测/隔离集成覆盖编码、git/non-git、路径恶意输入、双 Key 并存、全部服务端意图入口、四 runner env/spec、TALK session store、CAS 和伪造 health，以及 legacy 回归。Windows 必须在隔离目录创建真实 junction：根、祖先、末组件分别指向内外，检查拒绝及外部哨兵不变，增加替换竞争；权限不足报告 not_run，不能用 mock 冒充。静态测试单独不足以证明 TOCTOU 已消除。

Key 错误码建议仅在真实越界时使用 key_root_inside_repo，分别映射 key_root_mismatch、workspace_path_unavailable、workspace_link_refused、workspace_shape_unknown、workspace_id_invalid，统一 worker/provision/runtime；兼容和 HTTP 状态码在实施包固定，不暴露秘密和私人路径。git 新编码文件名与 legacy 旧名同时保留，无回退和迁移。

W3c 需另行授权，在两个真实外部项目、隔离服务/DB/端口及测试身份下，逐 runner 验证创建、原生运行、切换、A stop 后 B 持续运行、同项目两角色 HOME/session 和重启恢复；无法取得真实 CLI 或登录则记录未验证。模拟不能代替真实通过。

待用户决定及建议：①是否按 runner 分批开放，默认四种全部验证后统一开放；②绿色版随目录携带明文 Key，默认按既定决定并在用户文档提示；③CLI 绕过 HOME 或 session 位置不可证明时，默认该 runner 继续拒绝；④多 runtime 争抢同角色默认沿用 owner/claim/generation，不自动接管；⑤未知旧文件、根重定位和 pending 意图默认不自动迁移、覆盖或执行。这些均为建议，不表示已获授权。
