## 用户可见行为

- 当前发起会话在主动模式下，派发自己的任务后自动进入有限跟进；交付到达后读取完整摘要/必要原文，依任务约定核验、独立复核或集中返修，确认后收取；遇到需人工澄清/验收即停止自动推进并通知。
- 被动模式保持派后结束、用户通知取件。切回被动或模式版本/身份/任务归属改变，停止当前跟进，不取消或重派执行者任务、不重启服务。
- 不盲信runner succeeded或执行者自报；自动跟进程序不能代替语义审查。主动收取必须带发起者核验声明/证据引用，复核result_message_id及正文SHA未变，再走专用原子守卫收取API；原人工收取保持。

## 实施边界

1. 每个MCP连接内有有界发起者跟进状态，明确绑定实际API身份、项目、模式版本、显式任务集合、单次W/客户端T/余量/有限总预算。由单调时钟强制总预算；只承接本请求派发的任务和明确加入的复核/返修，不扫描全项目、不自动新开无关工作。
2. 连接级状态不是服务端权限或固定主控，不新增DB授权表/会话租约，不冒用其他成员Key。启动/每次取件与收取/新复核派发前重核身份、项目模式/版本及created_by；旧API权限与人工被动调用保持。
3. 已配置明确客户端预算的MCP入口在active下派发后返回可信的下一步跟进指引/连接内状态；新follow工具执行有限等待和交付工作项返回。语义核验、代码修正仍由发起模型按授权执行，不把不可信报告文字直接执行成工具动作。执行者/复核者不依赖模式推进下一片。
4. MCP等待独立处理，读取取消通知，同一连接不再被长等待独占。等待并发数有界；重复等待明确拒绝，不无限排队。取消或EOF只结束读等待/跟进，不取消后台任务；HTTP中断仍受socket边界，明确记录响应分类，不宣称任意慢IO硬实时。
5. 单次W+返回余量<=实际宿主T；客户端预算必须有来源，未知时不自动启用主动跟进。入口接受明确预算配置，不借其它终端值推断；默认现有passive行为不变。执行者24小时预算不随等待更改。真实宿主T/W/余量、正常命中/到期、取消和同连接后续查询必须有证据。
6. 项目仍保存mode意向；仅当前连接确实在跟进时返回局部effective状态，不能伪造所有会话/全项目都已生效。断开重连不自动恢复旧动作或补发写操作，需读当前任务再明确开启新跟进，未知写入结果不盲重试。

## 实现接口

- `talk_follow_tasks` 为第十个独立stdio工具（bridge含延迟send共十一个）。`start`登记本人的显式任务；`next`返回新的或已变更的交付、正常到期、人工门禁或停止；`collect`要求读过的稳定引用和非空核验声明/证据；`stop`只停本地跟进。已读取未收取的原任务不会阻塞复核交付；已有待核材料可用原`talk_get_delivery`补读。
- 配置明确T/W/余量/总预算后，active下`talk_delegate_task`自动登记连接内跟进；下一复核/返修派发沿同一deadline。默认未配置不自动进入，passive保持原派发行为。
- `POST /api/tasks/followup`在真实`BEGIN IMMEDIATE`写事务内复核模式/版本、既有批次任务的created_by/项目/根控制状态，再调用原创建逻辑；`POST /api/tasks/{id}/collect-followup-result`在同样事务内复核模式、归属、根控制和结果ID/正文SHA/作者/Hall/撤回。无DB迁移；旧服务缺专用路由即拒绝，不退化成忽略条件的旧写入。
- 明确4xx拒绝与未知5xx/传输结果分开；后者即使实际已提交也只报告outcome_unconfirmed，要求读当前状态，不自动重放。被动/人工旧入口保持权限及原语义。
- 新stdio等待通道同时允许正常查询/ping，最多一个等待，重复请求立即拒绝；匹配JSON-RPC取消ID或EOF结束读等待。该能力不外推给旧Pi直接工具或其它未接通入口；各宿主T仍须分别实测。
