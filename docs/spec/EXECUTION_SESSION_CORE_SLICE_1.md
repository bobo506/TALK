## 实现边界

新增单一标准库模块，内部类型和函数名可自行设计，但必须有一个统一规划入口，完整串联数据校验、会话选择和投递内容生成。不得只写未被统一入口调用的分散helper或交付方案代替代码。

模块仅使用调用方显式传入的数据，不访问环境变量/文件/数据库/网络、不spawn进程、无import时副作用、不在模块内部创建/恢复真实会话。返回计划，不发消息、不写TALK任务状态、不产生原生session成功事实。当前生产路径不导入新模块。

### 会话范围和状态

- 分配者显式选择新建或请求续用指定候选，不根据任务标题、角色名或相似文字自动挑旧会话。没有候选即新窗；不同TALK任务可以续用同功能候选，不要求task_id相同。
- 候选与请求必须匹配：project、目标member、requester、显式工作线/continuity key、调用方已核验的真实工作区身份、runtime/runner、native home命名空间、provider/模型绑定配置及有效配置/权限指纹、服务launch和会话generation、首轮基础合同版本/哈希。会话generation在同窗口内稳定，不是每个任务不同的execution id；不同任务的task/attempt/execution身份用于本次增量、留档及防重放，不能要求两个独立任务的这些ID相同。采用结构化规范JSON等无歧义比较/指纹，不直接拼接字符串；配置绑定不冒充实际后端模型证明。
- 真实路径解析、身份/权限/独占核验由以后接线层完成，本片接收明确的身份值及已确认事实；缺失/未知不得默认为匹配或独占。不要仅做路径lowercase后自称真实目录身份已核实。
- 候选busy、有活动writer或无法证明该角色执行通道可独占时返回等待/拒绝投递计划，不通过同home另起fresh绕过；tainted/closed、范围/配置/会话代次变化则不续用。计划不能清owner、抢占或恢复旧进程。
- 新窗计划不伪造native session id；实际创建/保存/ACK、投递幂等和跨进程锁均不在本片声称完成。

### 上下文指标与60%判断

- 数据取自显式输入的上下文投影，优先合法`projectedTokens`，没有该字段时才考虑合法`pressureTokens`，容量为`contextWindow`；输出标记来源为预计值或最近请求值。字段缺失不同于显式0。
- 只接受合法非负整数token数与正整数容量，拒绝bool、数值字符串、负值、NaN/Infinity及超出JSON/JS安全整数范围的数据；已提供但非法的优先字段不能悄悄回退成一个看似可靠的低占比。
- 指标须能关联同一候选/当前模型配置/会话修订。采样时间和当前时间、允许最大样本年龄由调用方显式提供，本片不擅设产品级秒数；缺失、过期、来自未来或身份/修订不能核对的样本记未知。token-meter分子分母独立更新，不能只看字段存在就宣称同次请求一致。
- 用原始整数比较60%（例如`used * 5 >= capacity * 3`），不取UI百分比、不先四舍五入。59.9%可续用；60%及以上新窗。使用量超过容量仍按达到阈值处理；没有10轮硬限或后备计数限制。
- 在执行通道可用前提下，已有候选指标未知时返回新窗完整计划并给出可审原因，不填0%、不复用未知候选。没有候选的新窗首轮无需旧指标，不能因缺指标循环生成空窗。
- 决策发生在下一条指令投递前，只生成计划，不中断当前任务。计划应包含机器可读action/reason和可得原始计数/来源，错误不回显原prompt、Key或私有配置值。
