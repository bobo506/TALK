## 判定优先级

1. **先范围与通道。** 同一角色、project/requester/工作线、已核真实工作区、runner/home、provider/model配置绑定/权限、service launch、会话generation及基础合同匹配且首轮确认送达，才可考虑续用。同功能不同task可续，不要求task/attempt/execution相同。不同功能/范围/配置不匹配按既有新窗规则；busy/有writer/无法独占先wait，不能用兜底同home另起窗口绕过。
2. **再可靠占比。** 合法当前占比<60%继续原窗，即使已经交办10次以上也不因轮数换窗；>=60%下一次交办新窗，计数再小也不能兜底拖延。不变更原始整数判断、projected优先、非法优先字段不回退的合同。不得用未知覆盖已有可靠>=60%的换窗决定。
3. **仅缺少可靠指标时才检查备用计数。** 由可信调用层提供与该精确窗口/作用域绑定的指标不可得证据及完整计数；已确认交办数<10可再交办一次，第10次可投递，第11次须新窗。无可靠计数、无明确分类或不能证明从首轮累计，不启用兜底，仍给新窗完整计划。有效指标恢复时回占比规则，计数仍持续保留；下次再缺数不能从0或从缺数时刻重计。

新窗完整基础正文＋本次增量/必要新Hall，续窗仅增量/新Hall，留档合同引用与投递回执校验、输入不变及任务权限保持。十次仅备用限制，不能声称可保证上下文不超过60%或减少费用。

## 不可得原因与证据不能混淆

当前289把unknown统一为`context_sample=None`，不能据None就断定只是没读数，否则错模型/错会话也会被误续。本片必须把可审、机器可判的不可得分类传到统一规划入口；新增参数/返回字段和helper可自行设计，但不能只有未调用的helper。可信来源是调用层明确事实，不声称实现跨进程认证。

- 可考虑兜底：明确未提供/暂不可用的指标、尚无用量样本、缺合法容量或来源明确但已过期等单纯不可得。必须使用有限白名单，并核对候选身份/配置、当前通道及窗口计数来源；只说unknown、不认识的reason或裸None不应自动获准。运行器明确不提供能力可由可信宿主按精确scope/window确认，不伪装为有效占比。
- 不可兜底：会话/代次/修订/model/launch/工作线/基础合同不符，producer/schema未知，显式非法数字或字段状态矛盾，未来/来源超cut或顺序矛盾、事件缺口/冲突、来源身份无法核验、错误原文和模糊异常等；保unknown/既有新窗或等待，不擦掉错误改称missing。
- 当前原始样本校验发现禁止类原因，优先于任何“可兜底”标记；不能靠调用者传`allow_fallback=true`或低pressure绕过。289原有unknown→None兼容可保留，但应附明确分类和关联证据；组合入口须验证这些信息并以实际校验为准。
- 可信状态若记录该窗口最后可靠占比已达到60%，在缺数时仍必须换窗；不能丢失此事实再用不足10次拖延。纯状态可显式保留已核阈值观测，观测更新不增加交办计数；有新的可靠占比时按本节第2条判定，不把旧读数伪装成当前值。未曾观测与“已知低于60%”须分开，不把未知填false/0。
- 首个新窗无历史指标不需要兜底，本来就走完整首轮；不得因缺占比循环生成空窗。原生ID/送达事实没有建立前不能伪造计数或称已创建/已发送。

## 窗口计数纯状态合同

本片不读写数据库/文件、不发送消息，不实现真正ACK或锁。实现可复用的纯状态初始化/确认投递归并（命名自定）和规划衔接，输入由未来可信宿主提供并证明来源；返回新状态/待提交意图，不原地改输入。

- 计数绑定精确native session ID、稳定会话generation及规范JSON作用域指纹（含project/member/requester/continuity/workspace/runtime/runner/home/配置权限/launch/base版本哈希），从新窗首轮累计。任务ID不同不重置；新原生窗口/代次独立初始化，不能由调用新函数或读数恢复重置旧窗状态。
- 仅确认已经进入该原生窗口的正式任务/后续指令计一次，完整首轮也计一次；普通模型工具调用、原生内部多步、预检、dry-run、重复规划、未投递失败不计。成功进入窗口之后再取消/超时，原指令已经消耗上下文，不能倒扣。
- 实际投递身份应可去重（任务/attempt/execution及独立directive/delivery ID与正文SHA等），同一ACK/重试回执幂等；相同身份不同正文或窗口事实冲突不能静默覆盖，数据不可信时不能兜底。计数须为安全非负整数，拒绝bool/负值/越界；候选已有确认首轮但计数为0或计数来历不完整应判无效。
- 每次规划不得预增计数，也不能因多次判定消耗轮数；返回的“允许第n次/计数意图”须说明待真实送达后才能归并。通过纯归并测试证明失败/重复不重计、ACK后恰加一；10不是模拟成功ACK。
- 计数状态损坏、缺失、错scope/window/generation/launch/base、未知历史覆盖、重复冲突或修订回退，都不能伪造新鲜可信状态。默认旧调用无此证据时保持unknown→新窗；不自动迁移旧生产会话/owner或假造首轮记录。
- 当前有可靠<60%指标时不因缺计数而强制换窗；但缺计数期间不能凭记忆补造完整历史，下次指标缺失时须新窗。计数和指标来源分别验证，不能因某个允许条件掩盖其它守卫失败。
