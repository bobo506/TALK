## 现状与身份合同

- 中央数据库不拆分。项目的权威身份是 DB 的精确 `project_id` 和登记的规范化真实源码根；项目目录的 `.talk/project.yaml` 只作为项目与服务器选择指针，必须与 DB 一致。缺失、冲突或不合法时停止并提示，不从 workspace.json 猜项目或自动改 DB。现有初始化还会创建其他文件；新指针模式不能删除旧文件。
- 现有角色 ID 使用项目和名称的 slug 加随机后缀，项目 slug 可以碰撞；成员主键检查和冲突拒绝/重试保障不会复用成员。名称按现行 strip 后精确比较，同项目同名冲突，归档后新建新 ID；不同大小写保持现有行为。跨项目独占身份守卫不得放宽。
- 角色请求由页面绑定当前项目发起，经 worker claim、租约校验、角色创建、Key 私有落盘、档案准备及 ACK/report；DB 与文件系统不是同一事务。直接 POST 创建角色只一次返回 Key，不自动写文件。保留名称唯一性、operation_key 幂等、不重发 Key、锁及资格检查。
- 持久化的角色级 `storage_layout` 是唯一布局判据：现有角色、导入和旧未完成请求为 `legacy`，新角色创建事务显式写 `workspace-v1`；新请求创建时冻结布局。新老角色可同项目共存，禁止依目录、名称、创建时间推断布局，禁止旧 Key、身份档和历史迁移。
- 安全目录组件建议精确 ID 的 UTF-8 无填充小写 base32，项目加 `p-`、成员加 `m-`；验证非空和组件长度，过长拒绝，禁止截断。实际标识仍用 DB 原值；创建及打开时校验规范路径、符号链接和 Windows reparse point，防止逃逸，不能只比较字符串前缀。
- 新布局身份档位于 `workspaces/<p>/roles/<m>/profiles/{IDENTITY,SOUL,USER}.md`，用带根类型的受限相对引用登记；服务端按项目、成员和布局验证解析，拒绝伪造、`..`、错误 basename 和布局不匹配。旧角色继续使用原 `.talk/agents/` 路径；缺失不回退到另一布局，两套并存时只按持久版本选择，冲突拒绝。profile API、worker、CLI 和 host 消费者应统一合同。cwd 仍为真实项目根，同 cwd 不提供源码访问隔离；HOME/session/日志/stop 的运行隔离留 W3b。

## Key 的部署形态合同

可信共享路径 resolver 以规范化 TALK 数据根本身的 `.git` 判定：目录或文件均表示 git 工作区（含 worktree）；明确不存在才视作非 git 数据根。无法访问、无法确定、链接或路径安全校验失败时拒绝写入，不降级为绿色版。部署形态、可信派生路径在请求创建时冻结，重试重检；形态或根变化则停止并要求人工处理。浏览器不能指定 Key 根。

- git 工作区：新角色 Key 一律在 TALK 目录外的私有 Key 根，例如 `~/.talk/keys`；保持拒绝仓库内 Key 的所有守卫。
- 非 git 绿色版：新角色 Key 在 `TALK/keys/<p>/<m>.key`，其中 p、m 为上述安全编码；仅对可信数据根精确派生的 keys 子树允许例外，不能授权任意源码路径或链接逃逸。即使数据根与真实项目根相同，也只允许这一精确子树。
- 旧角色继续使用原先登记或配置的 Key 路径，不迁移。worker、provision 和 runtime 现有多处守卫与消费逻辑必须统一此合同；W3a 禁止所有入口启动新布局角色，W3b 处理实际运行及新老 Key 根混用。Key 私有权限、避免日志和响应泄漏；不加密。`.gitignore` 在实施时追加 `/keys/`、`/workspaces/`、`/runners/`，打包提示 zip 含明文秘密。

以隔离根验证 `.git` 目录、worktree 的 `.git` 文件和无 `.git` 三种情况；核验 git 形态的仓库内拒绝、绿色版的精确子树例外、其他源码路径和链接逃逸拒绝、无法判定、形态变更重试、旧角色不迁移和绕过页面启动的拒绝。不得读取真实 Key。

## 谁创建目录及恢复

页面只提交角色请求，不提供工作区创建或管理功能，也不传目录；服务端角色创建 DB 事务只持久化角色及布局，不创建目录。可信 worker 在 claim、核验项目、指针、布局、请求归属及租约后，调用服务端共享 resolver 对应的受限文件系统操作，负责创建 `workspaces/<p>/`、`roles/<m>/profiles/` 和写入 `workspace.json`。后台创建内部存储目录不构成页面创建或管理工作区，不与产品决定冲突。直接 POST 仅保存 DB 并一次返回 Key，不承诺自动创建这些目录。

`workspace.json` 是可重建缓存而非权威来源，记录 schema、精确 project_id、规范化根、显示名和创建时间，不含 Key；存在时必须核对 ID 与根，冲突拒绝，不能覆盖。只读访问和旧角色访问不创建。指针仅在显式终端注册流程、DB 登记及根绑定确认后写入，冲突拒绝。

建议顺序：冻结请求、布局和部署形态 → claim 并核验 → 逐组件检查安全、以私有权限创建或验证项目目录 → 同目录临时文件加排他发布 workspace.json → DB 创建角色及保存布局 → 私有原子写 Key → 创建或验证角色目录和档案 → 复查租约及资格后 ACK/report。workspace.json 发布必须不可覆盖；并发竞争失败方重读并验证。目录存在不等于开通成功。

并发由请求租约、角色锁与排他创建控制；每次副作用前后复查资格、布局、成员归属、credential version、文件身份与安全路径。已有目录或文件无可信归属证据、归属冲突或权限不安全时停止并人工处理，不认领、不覆盖、不删除未知目录。项目目录半创建时仅可在能证明归属时幂等继续；Key 已写但角色目录创建失败则保留 Key，确认同一操作后续写，不生成第二成员。Key 生成后丢失或身份不可证明时沿用现有失败/人工恢复，不重发 Key。DB 和文件系统跨事务，须测试每步前后崩溃、租约失效、并发与重入，不能把目录存在当成功。

## W3a 实施边界与验收

## 运行器目录预留（后续独立切片）

```text
TALK/
  keys/<project_id>/         # 仅非 git 数据根的新布局 Key；组件实际安全编码
  workspaces/<project_id>/   # workspace.json、roles/<member_id>/、未来 tasks/runtime
  runners/<runtime>/          # 预留运行器级适配数据及元数据
```

`runners/<runtime>/` 只保存运行器级模型清单及别名、思考强度选项、版本适配基线、探测缓存等；由代码默认值生成，可覆盖、可重建。不放凭据或登录态（仍在角色 native HOME），不托管 CLI 安装本体；与私有 `keys/` 和按项目角色隔离的 `workspaces/` 分离。W3a 不依赖该目录，除 `.gitignore` 预留外不创建目录或增加运行器目录业务逻辑；后续独立切片定义实现与验证。

其他非目标：拆库、加密、历史角色/Key/HOME/session 迁移、安装器、打包器、自动修复冲突、页面创建工作区和跨角色源码访问隔离。根重定位的显式登记流程及组件超长处理留后续设计；冲突时停止，不自动覆盖 DB 或截断身份。
