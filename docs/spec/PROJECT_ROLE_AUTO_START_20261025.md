## 用户行为与范围

- 每个项目角色保存“随项目自动启动”，缺省false；只有human可改，不改现存角色选择、运行器/模型/Key/绑定/权限。保存只影响下次实际项目后台加载，不立即启动/停止角色。
- 实际加载定义为本项目统一runtime的新一代正常启动，包括正常重启和关机后恢复；页面打开/刷新/轮询/切换导航不触发。每代只处理一次保存的选择，本轮人工关闭后不自动再拉起，已经正常运行的同一服务不重复启动。
- 只通过原受管start核心创建新launch/实例，启动就绪仍由真实宿主回报。失败按原错误反馈，不把“已入队”当“启动成功”。删除/归档/禁用/离册/不受管/未配置角色不自动启动，旧墓碑不能因自启动恢复。
- 异常关机：未选择角色在严格证明旧归属已停止后收敛为stopped；选择角色在相同证明后才重新入队。只认本机内核启动时间及原launch/实例/manager一致、全部旧记录在本次boot之前、原进程已退出且无替代进程的证据；不凭心跳/PID单项解除未知归属，不强杀/接管进程。
- 在途任务/残余claim/lease或身份/代际不符仍阻挡，任务和原结果不取消/恢复/重写。原明确paused且领取完全撤销的根任务例外沿既有恢复规则，286不改。当前boot遗留未知归属继续人工处理，不扩大为无限自动清理。

## 实现约束

独立设置表和每runtime代/角色的启动审计记录，不给旧project_roles追加需回填的强制列。设置与执行状态分开，公开投影不含私有路径/argv/Key/token。角色删除同事务清设置，历史启动审计可保留。

runtime生成activation_id并写入原私有健康记录；human-only执行入口按精确本机DB/项目绑定、当前健康代/进程与新鲜度校验，不能由页面或任意ID重放制造新加载。每代/角色记录保存当时选择及服务generation，手动操作或设置变化优先；启动入队与完成记录同事务，网络重试/API重启/并发不重复创建launch。领取使用限期lease，迟到执行不能覆盖新轮。

冷启动证明复用原本机恢复检查，只有内部已验证preboot路径可跳过旧90秒心跳等待和作废明确preboot动作；公开人工恢复接口不新增绕过参数。恢复CAS与本轮审计generation同步提交，不伪造心跳/ready。

startup请求运行在runtime独立IO线程，不阻塞主循环健康；完成旧归属收敛之前不先创建替代宿主。单次HTTP等待65秒，服务轮次预算55秒（留足返回余量，开始重证明前保留45秒），最多8轮，普通待处理间隔5秒、连接错误退避5—30秒；processing返回剩余lease等待（最长120秒），给API重启留下回收窗口，避免在租约到期前空转耗尽轮次。执行lease120秒；异常/超时如实反馈，不无限重试。正常关闭先标记stopping，等待在途启动调用退出，再沿原流程关闭；服务端每次写前复核当前runtime仍有效，不能在旧后台退出后迟到重新拉起。
