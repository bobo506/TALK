# 角色执行时限与删除角色：已确认需求


> 2026-10-17进展：260首次实施[产品片B](ROLE_HOST_RUNTIME_CONFIGURATION_DESIGN.md)，仅闭合受管宿主内置配方的默认21600/显式覆盖与逐runtime模板，不改bridge全局600/旧手动入口或运行中的实例。原生/实际预算、全入口统一仍待后续验证，不把下文旧启动参数盘点当当前实例实测；删除仍另片。

确认日期：2026-10-16（Asia/Shanghai）。来源：项目管理者本次明确要求。

状态：**全角色统一与删除功能待分片实施、验收**。2026-10-16 旧 K2.8 的 6 小时入口修改经任务 252 独立复核通过并收取，本轮发布该入口；实际运行实例仍需空闲后重启。其它角色尚未统一，删除按钮尚未实现。

## 1. 所有角色启动默认执行 6 小时

- 所有接入 TALK 的角色，无论模型、业务职责、存量或新建，启动时统一默认单次 CLI 执行预算为 **21600 秒（6 小时）**。包括手动 bridge 入口、受管启动配方及新角色配置成功后的自动启动入口。
- 继续允许通过明确的启动参数覆盖预算，包括按大任务需要指定更长的正整数秒；不保留固定 3600 秒的入口上限。迁移时也须检查旧脚本中显式的 3600 秒参数，不能只改通用默认值却仍被旧启动参数覆盖。
- “单任务 6 小时”在当前 bridge 中按**一次 CLI 调用**计时，不是整个常驻服务寿命，也不包含 TALK 排队、等待人工澄清、完成后等待收取等时间；多阶段调用不能据此宣称整个任务已有统一硬截止。
- 启动预检、命令预览、实际执行及预算报告必须使用同一个有效值。已运行实例保留启动时参数，在空闲并正常停止后重启才采用新值；不能中断在途任务来强制切换。
- 本要求只调整执行预算，不把 MCP 客户端超时、TALK 读取等待、主动等待策略、HTTP 超时或任务租约一并改成 6 小时；仍按[终端预算核验要求](../guides/TERMINAL_MCP.md#终端适配必查工具超时与等待预算2026-10-06)分别核验。也不覆盖外部桌面聊天自身的宿主限制。
- 当前事实：通用 bridge 代码默认仍为 600 秒，DeepSeek 当前启动参数已只读核到 3600 秒，Kimi K3 最近启动记录为 3600 秒但当前未运行；旧 K2.8 当前实例沿用旧值，新 K2.8 未启动。252仅覆盖已通过的旧 K2.8 入口；其它入口仍需独立实施和验证。本轮没有重启任何角色。

## 2. 删除角色按钮与清理范围

- 在角色详情的“角色开关”区域，紧邻“启动”“关闭”增加 **“删除角色”** 按钮。操作对象是当前项目中的所选角色。
- 删除成功后，该角色从本项目角色列表及可分配对象中移除，不能继续启动、接任务或通过“绑定重置”恢复旧配置。
- 清理该角色在本项目的运行器/模型绑定、说明与权限配置、本机身份档、角色专属启动/接入配置、私有 Key 及可用于恢复接入的角色专属元数据。删除不只是隐藏或保留完整配置供恢复的归档。
- 历史任务、交付结果、Task Hall 消息及历史归属保持可查看。为历史引用可保留最小身份标识或展示名快照，但不能借此保留可重新启用的完整角色配置或有效凭据。历史任务的公开绑定快照不等于当前可用配置。
- 以后再次需要，只能走“创建角色/保存并配置”重新添加、重新绑定和生成凭据；新建角色获得新的身份，不重新启用旧配置，也不把旧任务改挂到新角色。
- **用户补充示例（2026-10-16）**：项目内有两个 K2.8 时，删除其中一个，只移除这个角色及其配置，另一个 K2.8 继续保留。以后需要再加一个 K2.8，必须重新点击“创建角色”添加，不能通过恢复旧配置把已删除角色找回；原角色历史任务仍可查看。
- 只清理本项目、本角色拥有的配置与资源。不删除模型本身、共享运行器、全局原生登录或其它项目/角色的配置与凭据。共享旧身份必须区分本项目接入与全局身份，不能为了本项目删除而让其它项目失效。
- 沿用已确认的在途保护：运行中先正常停止本角色服务，有未结束任务先处理；不静默丢结果、不自动强杀未知进程、不连带取消其它角色的任务。删除前需明确展示删除与历史保留范围；清理失败须显示未完成项，不能提前宣称全部删除成功。具体删除协议、共享身份隔离及宿主清理重试在实施片中设计并独立复核。

## 3. 与原合同及实施顺序的关系

- 本需求补正[生命周期合同](ROLE_LIFECYCLE_DESIGN.md) §9.3、I20 中“保留绑定/说明/策略配置”的旧方向：后续必须删除角色配置，仅保留历史所需的最小引用。原合同的 human-only、其它项目隔离、在途任务与受管进程所有权保护继续有效。
- 252已按原包独立通过并收取，只发布旧 K2.8 入口预算补正；全角色预算统一另片安排。删除角色继续作为 R1-4 的独立功能片设计、开发、独立复核及人工验收，本轮不启动该功能开发。
- 操作手册同步记录在[用户操作手册的待上线调整](../guides/USER_MANUAL.md#已确认的角色管理调整待上线)，当前页面仍以已发布功能为准。

## 4. 后续验收重点

1. 逐入口验证旧/新角色默认值为 21600，显式覆盖能贯通检查和实际执行；使用假 CLI/缩短测试预算验证，不以真实等待 6 小时替代参数证据。
2. 验证原 MCP 等待与其它超时保持各自合同，已运行实例迁移不干扰在途任务。
3. 删除按钮位置、真人权限、运行中/在途拒绝和清理失败反馈符合本需求。
4. 删除后角色和可恢复配置/有效专属凭据均不可再使用，历史任务、消息、成果与旧归属保持；重新添加得到新身份。
5. 共享运行器/模型/原生登录、其它角色及跨项目引用不受影响；实际宿主私有文件清理提供独立证据，不能只以数据库归档代替完成。
