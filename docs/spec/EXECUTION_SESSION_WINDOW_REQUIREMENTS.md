# 执行会话选择、首轮完整与续轮增量需求

更新：2026-10-20（Asia/Shanghai）。本文件记录用户在287复核收取后的需求澄清与本轮使用说明要求。当前功能尚未实现，本文不构成新实现/取证切片的派发授权，不改写287原交付或历史验证。

## 已确认的机制

1. 由任务分配者按工作关联性选择新建执行对话，或让同一角色继续已有对话；例如同一功能的多个切片可以续用。角色不永久绑定单一对话，分配者可以提前换窗。
2. 每个新执行会话的首轮应带入当前完整任务介绍所需的项目背景、角色职责、固定规范、范围/授权边界、交付格式和恢复状态。完整指可独立开工，不要求复制整个项目历史。
3. 同会话后续轮次只发送本次任务和变化内容；未变化的项目介绍、固定规则、基础合同与统一交付说明不再作为新指令重复注入。任务号、当前目标、基线变化、授权范围变化及验收差异仍须明确；约束变化须补充必要差异或新开会话。
4. 协调角色生成任务内容和bridge拼装执行提示必须一起调整，不能在协调者已写增量后，又由bridge补回固定介绍或全量Hall历史。已有会话历史由原生运行器管理，不把旧记录再次包装成新一轮用户正文。
5. 用户初提每个窗口最多10轮；若保持该上限，第11次指令在投递前新建会话，并恢复首轮完整介绍。10是上限，可以提前换，不要求用满。系统应记录并强制执行边界，不能只依赖角色记忆。
6. 每个TALK任务仍保留自己的任务号、权限、Task Hall、交付和收取记录。多个任务共用执行会话不合并TALK任务账本；可通过版本化基础合同加本次差异还原完整任务要求，避免要求协调者每轮重新生成重复文字。
7. 用户要求机制写入使用说明；正式上线和人工验收前必须补齐最终用户操作说明，不能只留开发合同。

本次用户方向允许讨论“同功能的不同任务共用执行会话”，优先于287方案里仅考虑同任务修复的候选建议；287关于当前入口、usage未知、权限/并发等实际核查结论保持。新方向尚未转成已批准的实现切片。

## 10轮的判断与待定项

- 用户明确说明10轮来自初步设想，没有实测依据，并询问合理性。本轮工程建议：先保留10轮作为试用上限，允许派发者因功能结束、任务不相关或上下文增长过大而提前换窗；这不是已验证的最优值。
- 轮数不能等价token预算。一次任务可以产生大量工具结果和中间消息，短任务也可能只产生很少上下文。未来宜按实际输入量、可得缓存指标和交付质量观察后调整，不虚构节省比例，不在本轮擅自增加固定token阈值。
- 计数口径建议为向同一执行会话实际追加的一条正式任务指令计1轮，追加修正也计；模型内部工具调用/底层API请求不逐次占“交办轮”，独立预检另行处理。此为建议，排队取消、投递失败/重试、配置是否可调等细节待实现片确认。
- 10轮最终默认值、是否允许用户配置和可选的上下文量提前换窗规则仍须明确，不能把本轮工程建议写成已有产品配置。
- 同会话的新指令可以省掉重复背景，但模型请求仍可能携带此前有效历史。恢复会话不保证计费输入减少；真正收益必须按另获授权的实际样本核验。

依据：[DeepSeek多轮对话说明](https://api-docs.deepseek.com/guides/multi_round_chat/)说明其Chat Completions请求由客户端携带对话历史；[Anthropic上下文工程说明](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)强调同时管理提示、工具和消息历史等有限上下文资源。两份资料支持按内容量管理历史，不提供“TALK应当10轮”的实验结论；10轮的建议是本项目工程判断。

## 使用说明草稿（功能上线后转入用户手册）

以下说明描述待实现的使用方式，当前没有可操作入口，不提供虚构按钮或参数：

- 分配有关联的后续任务时，分配者可以选择继续该角色正在使用的执行对话；新功能或不相关任务可以新开对话。
- 新对话的第一次交办包含必要背景、规则和当前工作状态；继续同一对话时只交代新任务与变化内容，减少反复介绍。
- 若采用暂定10轮上限，该对话达到10轮后，下次交办进入新对话，并重新带入恢复信息；分配者可以更早换窗。
- 换执行对话不会丢弃或合并原TALK任务、成果和验收记录；Task Hall仍按任务分别查看。
- 同一对话不承诺固定缓存命中率或费用下降；大任务可能需要更早换窗。

上线时须按真实入口补充：由谁选择续用/新建、怎样识别当前会话与轮数、达到上限时的反馈、提前换窗/重置的方法、失败和重启后的提示。用户无需理解session id、prompt transport或profile等实现术语。
