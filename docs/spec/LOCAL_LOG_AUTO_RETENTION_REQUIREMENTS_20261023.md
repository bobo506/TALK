# 本机日志后台自动清理：已确认范围

## 用户已确认的产品方向

2026-10-23，用户认可留存/保护逻辑，并明确要求后台自动清理，不需要前台人工操作。该要求取代上一轮“本片只做人工预览”的建议；正常产品使用不应要求逐次点击、批准候选或执行维护命令。

用户随后明确“可以开工”，批准下列后台自动清理范围；本片Codex开发、DeepSeek独立复核。现有盘点首片282ac47和315/316结论保持。产品代码/隔离验证已经准备，独立复核与生产启用仍待，不把隔离删除等同于生产已清理。

## 已批准实现范围

1. TALK后台运行时每天检查一次；启动时发现已到期则补一次检查。后台未运行时不另外创建系统计划任务；重入、重复启动和多实例竞争须有互斥/幂等处理。
2. 默认保留30天，单个显式受控本机日志根1GiB软预算，可配置。超容量也不提前删除最近30天日志或越过保护；无法降到预算内时记录受保护量/原因。
3. 仅在已确认的日志根内清理，先取得可靠run关闭与所属项目/任务引用证据。活跃、未完成任务依赖、失联、归属不明或证据不足者保留；旧PID、无心跳、mtime不单独作为关闭证明。旧run不能证明时保持，不为了清理擅自改所有权或停角色。
4. 一次后台处理内部完成判定、目标快照、执行前重核、删除及结果审计；失败/并发变化如实记录并安全重试。预览作为开发排障入口保留，不作为日常清理的人工前置。历史引用需要可解释的到期/清理状态，不能先写删除成功再操作。
5. 本片不涉及私有`.out/.err`、桌面内部日志或未知日志根，不启用联网集中接收，不改角色启停/模型/Key/绑定/任务历史，286继续暂停。现有writer的每run轮换/清理需要与新后台明确协调，不能把原有自动清理说成新实现。

Codex开发、自检；DeepSeek独立复核，发现问题由Codex修正并定向复验。工作范围/会话状态相容时优先续用315/316原生会话，不强行复用不相容基础合同。

隔离验证必须实际证明：超过期限且满足条件的日志自动删除；活跃/未完成任务/归属不明/跨项目误归属不删；近期日志在超预算时仍保护；启动补检/周期/重复调用/多实例、删除失败和执行前变化均有真实证据；历史引用和审计正确；不需要浏览器保持打开或前台点击。使用独立临时根和假时钟验证，不通过直接删除现有生产日志来证明实现。

正式实现和独立复核完成后核验生产启用条件，不把“无需前台逐次操作”理解为跳过开发验收或直接清理未核实生产目录。详细实现/启用边界见[本片合同](LOCAL_LOG_AUTO_RETENTION_DESIGN_20261023.md)。
