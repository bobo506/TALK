# 忙任务停机保护与阻挡任务反馈

2026-10-25。用户已明确选择“先做忙任务停机保护，显示阻挡任务”，Codex开发、DeepSeek独立核实。上片退出进度/有限等待及337正常加载保持；本片不实现完整任务中断与恢复协议、不将仍可能执行的任务标为canceled。

## 行为与范围

- 人类关闭受管角色时，在原关闭写事务内检查该进程归属的正式任务：running或仍有claim_token/lease的记录；同目标、同当前实例及无法确定实例的残余执行均阻挡。明确属于其它实例的任务不被本次关闭影响。未领取、无租约的queued任务及已完全撤销领取的paused根不阻挡。
- 当前归属实例已报告busy或仍带current_task_id时也保守阻挡；没有实际任务行时只提示执行占用，不把消息/旧指针编号冒充正式任务。
- 拒绝为409，固定code、最多20个正整数任务编号、总数及busy布尔值；无任务正文/标题、Key、token、原生ID/私有路径。拒绝不改世代/动作/任务/租约/实例/归属，不提交关闭动作。
- 关闭与任务领取复用现有BEGIN IMMEDIATE。任务先领取则关闭被阻挡；关闭先接受则该角色/受管实例不能领取新任务。过期领取重排提交后必须重取写锁并检查最新关闭状态。现有任务续租/完成、非受管旧全局任务保持原行为。
- 角色页面关闭反馈显示阻挡任务编号或“执行占用”，任务结束后可重试；不排队自动取消/中断任务。后台普通stop沿原角色接口遇阻保留Popen/归属/API，stop --wait返回blocked并携带白名单化的任务引用；不强杀/清锁/CAS或伪报停止。

正式任务保护覆盖已领取执行及残余领取；对实例已上报占用采取保守策略。普通消息/未领取preflight的完整协同停机与原生子链退出证明仍不在本片，不能据本片声称整项异常恢复已完成。

后端角色关闭/任务claim守卫、纯数据白名单、宿主HTTP错误桥接及后台回执；前端仅已知错误的中文反馈与缓存版本，不做页面重设计。无新增数据库表或权限扩大。不改生产配置/Key/模型/绑定、自启动选择、250/286/旧报告，不读取生产DB/私有state/native/log。当前runtime4956/小Dgen80保持运行，不在开发/复核中生产停启或加载。
