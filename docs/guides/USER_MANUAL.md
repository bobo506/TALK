# TALK 用户操作手册

这份手册面向日常使用 TALK 的家庭成员或项目成员，介绍系统已经部署完成以后，如何在浏览器里沟通、委派任务和收取结果。

你不需要了解服务器、Python、Docker、API 或数据库。开始前只需要向管理员取得：

- TALK 的访问地址，例如 `http://192.168.1.23:8000`
- 你的登录密钥

如果你负责第一次安装或维护 TALK，请改看[家庭用户快速开始](./QUICKSTART_USER.md)和[部署指南](./DEPLOY.md)。如果你负责让 Agent 接入 TALK，请改看[Agent 开发者快速开始](./QUICKSTART_AGENT.md)。

> 操作章节描述当前版本已经可以实际使用的功能；应项目管理者要求，末尾另列已确认的待上线调整，不能作为当前可用步骤。

## TALK 的协作优势

**TALK 可以让多个开发任务独立推进，协调者通过多轮对话持续安排工作，不必把整个项目压在一次任务执行里。你可以逐步明确整个项目，而每次交给执行者的任务仍然很具体。**

这种方式允许你在开发过程中逐步补充和调整需求，比要求一开始就把整个项目的所有需求想清楚，更贴近日常软件开发。

例如开发一个网站，可以先确定公共的数据模型、接口和页面规范，再推进“用户体系”和“内容管理”两条线路。期间你可以继续与协调者讨论报表需求；等其中一条线路释放执行角色，再安排报表开发。每条线路都有自己的任务记录、交付和验收，不要求在一个回复里交出整个网站。

有空闲执行角色、任务边界和公共接口已明确、工作区互不覆盖时，可以并行安排独立工作；具体并发规模按项目约定执行。在被动模式下，已派出的任务可以继续执行，你也可以继续与协调者讨论和安排其它任务；后续派发和收取仍由你继续对话触发。

## 1. 登录 TALK

1. 在浏览器中打开管理员提供的 TALK 地址。
2. 在登录页面粘贴你的登录密钥。
3. 点击登录。

登录成功后，页面会识别你的身份并进入 TALK。登录密钥相当于你的密码，不要发给其他人；如果遗失或怀疑泄露，请联系管理员处理。

## 2. 认识任务、群聊与角色工作台

进入项目后，默认显示任务列表。左侧只列主任务，选中后右侧显示负责人、当前状态、成果和分工流转。可以搜索任务，或选择“全部 / 进行中 / 待我处理 / 已结束”；已结束包括完成、失败、取消，已提交但尚未收取的成果仍需要处理。

左侧任务条目显示“耗时 HH:MM:SS”：从助手领取执行到执行结束计算，不含排队或完成后等待收取的时间。执行中每秒更新，结束后固定；状态刷新可能有约5秒延迟。未开始、等待澄清或缺少有效时间记录时显示“—”；重试显示最近一次执行时长，超过24小时不回卷。

右侧先看状态提示，了解是否需要你操作。点击“查看成果”展开已提交的内容，按钮变为“收起成果”；再次点击收起，再点可重新展开。切换任务或项目后，成果默认收起。“查看完整对话”进入该任务的沟通记录；如果没有访问权限，页面会提示联系任务负责人。文件成果从完整对话下载。

“分工与流转”展示任务交给谁、每项工作进展和当前检查/测试结论。点击子任务可看其详情，再点“返回主任务”回到总览。“任务要求”默认折叠，展开可看最初填写的目标、限制和完成标准。

点击左侧同级的“角色”，列表首项为“项目设置”，其后为本项目配置的助手。“项目设置”显示项目开发要求、调度模式和宿主配置，搜索角色时仍保留此入口。选中具体角色后显示名称、成员ID、角色说明、角色开关和参与任务及执行耗时。详情空闲时显示“当前没有进行中的任务”，只说明工作状态，不代表服务在线。

角色列表保留名称、介绍、当前服务状态和简短绑定摘要，如“绑定：已绑定 · Kimi Code · K2.8 Preview”，省去后面的重复型号与运行器标识；成员ID行和空闲任务提示不在列表显示，有进行中任务时仍显示数量。详情保留ID，运行器/模型属性大块已移除。页面精简不会改变已有配置；配置是否可启动仍按角色开关的实际提示判断。检查步骤见[角色绑定页面验收](ROLE_BINDING_PAGE_ACCEPTANCE.md)。

在“项目设置”中，真人账号可以保存开发要求和调度模式；Agent账号只能查看。固定项目主控的指定、解除入口及角色徽标已移除；协调责任以每项任务的发起者为准，任何拥有现有权限并获授权的 Agent 都可以发起任务。

左侧标签依次为“任务 / 群聊 / 角色”。点击“群聊”查看普通聊天房间；任务专属沟通记录统一从任务详情进入。在窄窗口中，列表和详情上下排列。

### 创建与配置角色

真人账号在“角色”页点击“创建角色”，依次选择运行器、模型，填写名称与可选介绍，再点“保存并配置”。请求保存后会等待宿主处理；角色Key由宿主私有保存，页面不要求你复制。新建角色完整配置成功后，会自动提交一次该角色的启动请求，无需额外勾选；能否实际启动仍取决于宿主及运行器能力，以角色开关的实际状态为准。

创建入口列出已登记且未退役的运行器，并如实提示适配/控制状态。Kimi Code的模型目录为空且本项目已有完整K2.8绑定时，可先点“登记项目已有模型：K2.8 Preview”，登记后再选择实际模型。登记只保存现有公开型号声明；下架选项不会自动恢复，也不会替你登录或启动运行器。安装本轮后端创建校验修复后先重载TALK服务；后续只有静态页面更新时按Ctrl+F5刷新即可。

“项目设置”新增宿主配置。管理员准备好同机worker后，保存与其一致的宿主名称并开启配置；仅开启页面设置不会启动worker。宿主尚未开启时显示等待，在创建结果中可查看身份档案、本机接入配置和配置检查三步结果。完成配置后详情不再重复显示进度；处理中或失败仍显示必要的简短提示。

未创建角色的请求可以取消；配置失败可按提示继续。本机接入异常时，在角色详情“角色开关”下方点击“绑定重置”，按钮下的小字说明其用途。确认后修复本机配置，必要时更新TALK凭据并使旧凭据失效；该操作不重新选择运行器或模型，也不追加自动启动意图。不确定保存是否成功时使用“核对并重试保存”，沿用原请求。页面提示浏览器不能保留待确认请求时，先核对结果再刷新或关闭。

配置记录多时可能只显示部分记录，本页保存的近期请求会继续跟踪。旧角色没有配置请求关联或合法凭据代际时不显示绑定重置。自动启动未执行或投递失败时，详情会显示简短原因，配置成功仍保留；页面不会反复重试启动。旧页面留下的未确认请求沿原载荷核对，不追补自动启动。完整准备与验收见[创建配置页面验收](ROLE_CREATION_PAGE_ACCEPTANCE.md)、[自动首次启动页面验收](ROLE_AUTO_START_PAGE_ACCEPTANCE.md)和[宿主worker指南](ROLE_REQUEST_WORKER.md)；真人浏览器与原生登录、模型能力仍待验。

### 删除角色（独立核验已完成，待正常加载）

新版正常加载后，先在角色详情点击“关闭”，确认角色已停止，并处理该角色未闭环任务、未收取结果和定时任务，再点击“启动”“关闭”旁的“删除角色”并确认。页面会显示清理进度，完成后该角色从项目列表移除。

若显示“删除未完成”，查看列出的未完成项，排除占用或按提示正常重载后台后点“重试清理”。刷新页面仍会保留进度。等待后台清理期间角色已停止接收本项目的新任务；页面不会把未完成清理显示为成功。历史任务、结果、消息保持可查，重新添加须通过“创建角色”产生新身份；共享账号登录、模型和其它角色不随此删除。

本片已经独立核验并收取，尚未生产加载或删除现有角色；旧后端不显示删除按钮。正常加载后才能使用，具体安排见[加载方案](../spec/ROLE_DELETE_DEPLOYMENT_20261024.md)，验证记录见[删除切片](../spec/ROLE_DELETE_IMPLEMENTATION_20261024.md)。

如果提示独占身份归属未确认，先由管理员核对名册和共享引用，再删除；平台不会把仍有效的独占凭据当作已清理。共享身份在其它项目仍可按明确项目使用。通过API创建任务时，删除过项目角色的共享身份必须提供其仍在册的项目ID；当前没有项目范围的全局定时任务不支持继续向该身份派发，请先处理旧任务再删除。

### 启动与关闭角色服务

角色页搜索旁提供“全部启动”，列表每个角色只显示当前服务状态；成功时简写“启动成功”，不附带原生登录核验说明，也不重复显示先关闭再重启的操作提示，必要操作说明仍在角色详情。选择角色后，在详情的“角色开关”中点击“启动/关闭”；必要提示也显示在详情，服务状态从列表查看。真人账号可操作，Agent账号只能查看。新建角色配置成功只尝试自动启动该角色一次；打开页面或启动TALK不会因此自动启动所有助手。各角色仍需管理员完成实际适配与配置。

“启动中…”表示请求正在处理，“启动成功”需要服务确认就绪；“未启动（已关闭）”表示正常关闭，任务是否空闲仍看任务列表。不可启动的角色会显示原因。失败但原进程仍受管时，先点“关闭”并确认停止，再重新启动。

管理员已为本机绑定统一启动清单时，启动TALK也会恢复角色后台管理服务；角色本身仍通过“启动”运行。未配置该本机绑定的环境须由管理员启动对应后台服务。启动请求超过有效期仍未就绪，会显示启动失败；无旧进程归属的失败项可重试。

如果显示“运行状态待核实”，说明平台暂时无法确认执行端仍在线。请先联系管理员检查服务宿主，确认停止前不能重复启动。执行端恢复心跳后，页面会继续刷新实际运行状态；历史上的“启动成功”不代表当前一直在线。

如果关闭请求超过有效期仍未得到确认，会显示“关闭超时（状态待核实）”，并继续刷新。已配置本机启动绑定时，人类可再次点击该角色的“关闭”：平台核实原执行端确已停止、没有活动任务或其它执行端后，记录恢复审计并显示“未启动（已关闭）”，随后可重新启动。无法核实则保留原归属并提示原因；其它部署仍请管理员按[人工恢复指南](ROLE_SERVICE_RECOVERY.md)处理。已明确暂停且没有领取记录的根任务可保持暂停。

“全部启动”的独立反馈区分别显示请求、已启动、启动中、跳过和失败数量；已运行角色不会重复启动，安全失败项可在反馈区点“重试失败项”。只有提交请求时不会立即计为已启动。当前真实模型的登录与启动仍需管理员逐运行器验收；本轮页面检查见[受管服务验收](ROLE_SERVICE_ACCEPTANCE.md)。

退出TALK或关闭电脑前，最好先逐个关闭角色，等列表确认“未启动（已关闭）”。只关闭浏览器不会停止后台角色。关机后重新启动TALK，已绑定本机清单的后台管理服务会恢复，角色本身仍需点击“启动”；有遗留归属时先点击“关闭”核实恢复，再启动。“加载项目时按勾选自动启动”仍是后续计划。

后台管理服务启动时不再额外弹出Python黑色窗口；从终端启动TALK时，原启动终端仍照常显示日志。该修正须在后台管理服务正常退出后，随TALK重新启动才能生效；只重启API会保留旧后台服务和窗口。

### 查看和转移角色运行日志

人类账号进入“角色”并选中具体角色，在详情的“诊断日志”中选择“开始时间”和“结束时间”，点击“生成”；生成成功后点击“下载”，保存JSONL日志文件。时间跨度不超过31天。文件包含选定范围内已有的运行节点、日志及异常证据；出现“日志文件不完整”提示时，应保留该提示供分析，不能据此认定没有异常。

需要在其它设备分析时，在产生日志的设备上下载文件，再通过U盘或其它手动复制方式转移，交给分析工具或分析人员读取即可。当前日志工作按本机记录和文件导出组织，不要求集中上传到另一台TALK；不把文件复制等同于已经导入其它TALK实例。

日志读取与下载供人类账号使用，Agent账号无该读取权限；来源和时间范围影响文件覆盖内容。生成/下载不启动角色或调用模型，切换角色/项目及退出账号会清除旧下载上下文。历史错误属于对应实例，不等于当前新实例故障。

### 调整项目调度模式

进入“角色”页，点左侧首项“项目设置”，找到“调度模式”。真人账号可以选择“被动”或“主动”，再点“保存”；只选择选项不会提交。Agent 账号只能查看，页面提示“由项目负责人管理”。

“被动”表示派发任务后本轮结束，由你通知完成后再读取与收取。“主动”表达希望任务发起者在已授权流程内继续等待、取件、交独立复核及收尾的设置意向。项目模式只约束发起侧，执行者和复核者正常完成收到的任务，不因此获得额外派发权限。当前版本保存“主动”不会唤醒会话或自动开展这些工作，已结束的桌面对话仍需人工唤回。

页面分两行显示“已保存设置：被动 / 主动”和“实际执行：尚无生效的主动调度（本版本不支持自动生效）”。即使保存了“主动”，也应以第二行判断实际执行状态。保存意向不再依赖指定某个固定主控。

如果保存时提示设置已被他人修改，页面只读取最新状态，不会替你重新保存；确认已保存状态和自己的选择后，再决定是否点“保存”。如果自动读取也失败，“保存”会暂时不可用，此时点“重试”重新读取；“重试”不会写入设置。读取成功后确认最新状态；如仍需更改，再选择所需模式并明确点“保存”。读取仍失败可以再次重试。

离开“项目设置”（例如切到任务、群聊或具体角色）会放弃调度模式未保存的选择；返回时，选中项恢复为已确认保存的模式。停留在同一面板时，普通刷新提示或轮询不会吞掉你的选择。离页不会自动保存；若已点保存且请求仍在途，以服务确认的实际结果为准。

旧版本服务不支持该设置时，面板会明确提示并禁用保存。其他保存失败会显示原因，并在当前面板保留你的选择；离页后未保存选择仍会被放弃。未保存的选择不应当作已保存设置。

可按以下步骤验收本次修正：

1. 已保存“被动”时点“主动”，不要保存；分别切到任务、群聊、具体角色再返回“项目设置”，应恢复选中“被动”。
2. 显式保存为“主动”并等到成功提示，离页返回应仍选“主动”；此时点“被动”但不保存，离页返回也应恢复“主动”。
3. 确认“已保存设置”一行只有模式名称，没有括号和版本；停留本面板时，未保存选择应保持。

权限与异常恢复属于可选边界验收，没有条件可标“未人工验证”：

- **Agent只读**：仅使用管理员提供的现有Agent密钥登录查看；应能看到模式，控件禁用且不能保存。无需新建测试账号。
- **两窗口版本冲突**：两个窗口同一真人账号进入同一项目，初始都已保存“被动”。窗口A保存“主动”成功；窗口B保持仍显示已保存“被动”，不要刷新页面、切项目或点角色页“刷新”，再点“主动”并保存。B应提示被他人修改，只读取最新状态，不自动重写；读取后若已保存“主动”，保存按钮禁用。服务端对陈旧版本即使同值也返回冲突；选项等于本地已保存值时前端不会发保存请求。此步骤依据源码和独立探针，真实双窗口尚未人工验证。
- **冲突后的读取再次失败**：需要受控故障条件，可直接跳过并标未人工验证；不要求故意断网或改配置。该路径已由独立代码和恢复探针覆盖：重试可见且只读取，读取成功前暂禁保存，成功后按最新状态明确决定是否保存。

## 3. 任务分配与子任务

根任务由任务发起者分配，页面上不再提供“新建任务”入口；任务列表为空时也会提示“任务由发起者分配”。发起者派发新任务后，系统会自动建立一个独立的 **Task Hall（任务房间）**。一个 Task Hall 只对应一项任务，并固定连接任务请求者和执行 Agent，避免不同任务的讨论混在一起。

新任务的标题统一显示为“编号-任务名称”，编号就是系统分配的真实任务号（例如 `58-主控模式切换`）；不填标题时会显示为“编号-未命名任务”，项目由顶部选择器区分，标题中不再包含项目名。历史任务的旧标题保持原样可读。

委派分为两个阶段：发起者先指定根任务负责人；根任务开始执行后，再从根任务详情点击“创建开发 / Review / Test 子任务”，在共享弹窗的“子任务执行 Agent”中为每项子任务单独选择执行者。

写任务内容时，建议至少说明：

- 希望得到什么结果
- 有哪些必须遵守的限制
- 哪些文件、页面或信息属于本次范围
- 用什么标准判断任务完成

### 连续任务与执行对话

每项TALK任务都有独立的沟通记录和成果。“查看完整对话”打开的是该任务的Task Hall，不能据此判断执行助手是否沿用了上一任务的原生对话。

当前DeepSeek/DSH、Codex、Kimi Code和WorkBuddy内置独立CLI均已通过真实任务的同窗及新窗恢复验证。Kimi K2.8/K3共用一套适配，303—308已收取；WorkBuddy309—311也已收取，同窗计数1→2、新窗恢复计数1。开发均由当前Codex完成，未给Kimi安排开发工作；验后Kimi和WorkBuddy角色关闭，Kimi常规开发派发仍暂停。发起者先按同功能选择稳定工作线；可靠占用低于60%续用，达到60%后下一次换新；仅单纯缺数且身份/配置/完整计数可信时10次兜底，第11次新窗。首轮计1，工具/预检不计，读数恢复不清零，可靠低占用不受10次硬限。

2026-10-22随后新建的“workbuddy-k3”也已通过312—314同窗/新窗验证并收取。当前状态以角色页面为准。页面创建请求由配置服务处理；已绑定本机统一清单的环境会随TALK恢复配置服务及角色后台管理服务，角色本身仍按页面操作启动。

首轮在`execution_session.base_context`给完整介绍；续轮仅给同一`continuity_key`、首个`base_task_id`和本轮增量。换窗自动取回完整介绍，发起者不用重写；`force_new=true`可提前换窗。SDK/API已可用，MCP旧连接须重连并确认工具schema有`execution_session`；不传该字段的旧任务保持原行为。项目要求变化须创建新的基础任务。详[实际入口、示例及状态核验](EXECUTION_SESSION_USAGE.md)。

这里复用的是底层原生会话，不合并TALK任务Hall。WorkBuddy按用户批准的自带引擎独立CLI接入，已绑定本机清单时后台管理服务会随TALK恢复，随后可从普通入口启动角色；它不会控制原WorkBuddy桌面窗口。其它版本/模型、桌面GUI显示/手动续写及费用收益未据此验收。60%与10/11边界依据各适配的受控验证，详见使用说明及对应实查记录，没有为碰阈值消耗真实模型长上下文。

## 4. 在 Task Hall 中沟通

进入 Task Hall 后，你可以查看：

- 最初提交的任务内容
- Agent 提出的问题
- 你的补充说明
- Agent 提交的结果或失败原因
- 与任务相关的文件和回复记录

你可以像普通聊天一样发送文字、文件或针对某条消息回复。Task Hall 的记录会保留下来，因此重要约束应直接写在这里，不要只在其它聊天窗口口头说明。

## 5. 回答 Agent 的澄清问题

Agent 在正式领取任务前会先检查任务正文和 Task Hall 中已有的全部补充信息。如果信息不足，它会把需要一次回答的问题集中发到同一个 Task Hall；此时任务仍在“待响应”，不会被误显示为正在执行。

1. 打开该任务的 Task Hall。
2. 阅读 Agent 提出的问题。
3. 在同一个 Task Hall 中补充完整答案和必要文件；可以连续发送多条，不必压缩成一条消息。
4. 答复写完后回到任务详情，点击“提交 Hall 中最新澄清答复”。确认前，系统会继续把任务视为等待澄清，不会因为普通消息而自动开始执行。
5. 等待 Agent 重新读取完整答复、接受任务并开始执行。

每项任务默认只允许一轮澄清，复杂任务最多两轮。额度用完仍无法明确执行时，任务会暂停并显示“释放人工决策”。项目负责人可补充范围后继续，或明确额外开放一轮；系统不会要求 Agent 猜测执行。

## 6. 查看并收取结果

Agent 提交结果后，任务会进入“结果待收取”。

1. 打开任务详情或对应 Task Hall。
2. 阅读 Agent 的结果、文件和说明。
3. 确认结果已经成功送达后，点击“收取并完成”。

收取后，任务显示“已完成”，归入“已结束”筛选。“收取结果”表示请求者已经收到本次提交；普通任务不会因此自动获得质量结论。类型化开发任务的质量由独立 Review / Test 门禁判断，并在根任务详情中显示。

## 7. 取消尚未开始的任务

如果任务仍未被 Agent 领取，原请求者可以在任务详情中取消它。取消原因可以先写入 Task Hall，方便其他成员了解背景。

已经开始执行的任务可在详情使用“中止任务”，中断当前任务及其未完成子任务的执行，保留Hall、文件和已有成果。原“取消未领取任务”仍用于尚未开始的任务。

## 8. 管理任务树、Review 与里程碑 Test

根任务详情按当前状态和账号权限显示控制入口；只有开启委派权限且正在执行的根任务，才会提供创建子任务的入口。

1. 根任务进入执行后，Human 项目负责人可点击“创建开发 / Review / Test 子任务”；弹窗会显示“子任务执行 Agent”，这里选择的 Agent 只负责当前子任务，根任务负责人继续负责协调和汇总。根执行 Agent 会通过它接入的任务工具执行同一流程。
2. 创建开发任务时选择 `required`、`batch` 或 `exempt` Review 策略。高风险改动应使用 `required`；只有明确的低风险同批改动才适合 `batch`。
3. 开发结果冻结后创建 Review，并选择要审查的冻结任务。Review 通过后，详情中的结论会显示为“检查通过”。
4. 里程碑根任务必须再创建 Test。系统会预选当前完整冻结版本集；缺少 Review 或遗漏最新版本时会拒绝创建。
5. Test 通过后，根任务自动暂停并显示“里程碑待人工验收”。先阅读开发、Review 和 Test 各自 Task Hall 的结果，再点击“人工验收通过”。
6. 人工验收通过后，根任务负责人继续提交最终汇总；根任务进入“结果待收取”后，由根任务请求者按第 6 节收取结果，完成收尾。人工验收本身不会自动提交或收取根结果，也不会增加下一批开发额度。

如果 Review 要求修改，或 Test 失败，项目负责人可创建返工任务并选择触发它的质量任务。返工完成后，旧 Review / Test 不再覆盖新版本，黑板会重新显示待 Review / Test，避免拿旧结论冒充最新版本通过。

未结束的根任务详情还提供：

- “中止任务”：中断当前任务及未完成子任务的执行，阻止继续领取或创建后代，保留任务号、对话、文件和成果。
- 重新安排工作时，派发角色决定是否沿用原任务号：方向不变可以重新执行原任务，需要换方向则关闭旧任务另建。页面不再提供“授权继续一批”、风险暂停和整树终止的重复按钮。
- 中止不会冻结模型调用；重新执行是一次新的执行，执行者可以检查已有文件后继续处理剩余工作。

批次额度耗尽后，系统会允许已经创建的开发和Review安全收尾，再等待派发角色按现有权限安排。里程碑人工验收只确认当前冻结版本，不会自动增加开发额度；后端控制权限和预算规则保持。

## 9. 使用群聊

1. 点击左侧“群聊”，列表会显示当前项目的普通房间，以及历史上未归属项目的房间。
2. 选择一个已加入的房间，即可阅读记录、发送文字或文件、使用 `@` 提醒成员；任务专属对话不混在这个列表中。
3. 需要新房间时，点击“新建群聊”，填写名称、选择初始成员，再点击“创建并进入”。新房间会归属顶部当前选择的项目。
4. 可以搜索群聊名称或成员；明确获授权的管理账号可打开未加入的房间，只读查看且不自动加入。其它非成员显示“尚未加入”，需联系群管理员处理。

原来的“对话与房间”和全局消息流入口已从页面移除。已有任务对话仍可通过任务详情的“查看完整对话”访问，历史记录不会因此删除。

## 10. 遇到问题时怎么办

- **打不开 TALK 地址**：先确认设备与 TALK 服务器在同一网络，再联系管理员检查服务状态。
- **登录密钥无效**：确认没有多复制空格；仍无法登录时联系管理员。
- **找不到某个项目、Hall 或任务**：你可能尚未加入对应范围，联系项目负责人确认权限。
- **任务长时间没有响应**：在任务详情中查看工作进度，并在 Task Hall 留言；必要时联系项目负责人。
- **Task Hall 提示“自动预检连续失败，已停止重试”**：系统已达到该 Agent 的预检次数上限并将任务标记为失败，以免继续消耗模型调用。DeepSeek 默认只尝试 1 轮，其他 Agent 默认最多 3 轮；请联系管理员检查预检输出协议，修复后重新创建任务。
- **文件无法下载**：文件可能已过保存期限，向发送者索取新的文件。
- **页面显示与本手册不一致**：记录页面位置、按钮名称和截图，反馈给项目负责人；这也可能意味着手册需要随版本更新。

## 11. 当前版本边界

- 调度模式面板只保存项目意向，尚无自动生效的主动调度，也不会自动唤醒已结束的外部会话。模式按任务发起者理解，固定项目主控入口已退役。
- 运行中的单项任务仍不能独立取消；任务树可以整体暂停或终止，第三方 runner 需要实现同一控制探针才能及时停止本地进程。
- Review / Test 的结构化结论由执行这些质量任务的 Agent 提交，Human 页面负责查看门禁摘要和控制推进，不能在页面上手工伪造通过结论。
- Tester 的浏览器、隔离服务、API 和日志权限由管理员配置；仅把业务角色名称改成 `tester` 不会自动获得这些工具能力。
- 项目级 Members / Activity 独立页面和 observer 视图尚未实现。

这些能力只有在实现、真实验证并提供正式用户入口后，才会加入对应操作章节。

### 已确认的角色管理调整（待上线）

2026-10-16 已确认以下目标，**当前尚未全部实现或生效**：

- **执行时间**：角色每次执行默认允许 **24 小时**，页面不提供配置项。更新后，受管角色需先正常重载 TALK 后台管理器，再启动角色；已经开始的执行仍沿用原时限。排队、等人工回复与等结果收取不计入一次执行的时限。
- **异常日志留存**：后续完整保存异常类型、错误详情、调用堆栈及关联任务/角色/实例，重启后仍能追查原因；敏感凭据脱敏，页面提供必要摘要和日志定位信息。当前尚不能把只有简短错误提示当成完整日志。
- **旧角色统一受管**：本项目五个现有角色已保留身份、绑定和历史完成迁移，并于2026-10-18完成异常退出后的人工恢复及“启动成功”页面复验。可通过“关闭”确认停止，再“启动”完成手动重启；其它外部CLI入口仍需逐个适配验收。跨宿主重启持续在线尚未验证。详细范围见[日志与受管迁移需求](../spec/ROLE_RUNTIME_LOGGING_AND_MANAGEMENT_REQUIREMENTS.md)。
- **删除角色**：本片已实现详情入口、专属资源清理和失败重试，327/328独立核验与收取已完成，待正常加载。删除会从当前项目移除该角色，并清理其绑定、角色配置与专属接入凭据；以前完成的任务、成果和沟通记录保留可查。以后需要该角色时必须重新添加，不能恢复旧配置。
- 例如项目里有两个 K2.8，删除其中一个不会影响另一个。以后想再加一个 K2.8，必须重新点击“创建角色”，按新角色完成添加与配置；被删除角色的旧任务仍保留。
- 删除前需先停止角色并处理未结束的任务；不会连带删除其它角色、其它项目、共享模型或原生登录。

当前不要把“关闭”或“绑定重置”当成删除操作。新版步骤见上方“删除角色”，生产是否可用以正常加载及验收结果为准；详细范围见[已确认需求](../spec/ROLE_EXECUTION_AND_DELETE_REQUIREMENTS.md)。
