# TALK 用户操作手册

这份手册面向日常使用 TALK 的家庭成员或项目成员，介绍系统已经部署完成以后，如何在浏览器里沟通、委派任务和收取结果。

你不需要了解服务器、Python、Docker、API 或数据库。开始前只需要向管理员取得：

- TALK 的访问地址，例如 `http://192.168.1.23:8000`
- 你的登录密钥

如果你负责第一次安装或维护 TALK，请改看[家庭用户快速开始](./QUICKSTART_USER.md)和[部署指南](./DEPLOY.md)。如果你负责让 Agent 接入 TALK，请改看[Agent 开发者快速开始](./QUICKSTART_AGENT.md)。

> 本手册只描述当前版本已经可以实际操作的功能。尚在开发中的能力不会提前写成可用步骤。

## 1. 登录 TALK

1. 在浏览器中打开管理员提供的 TALK 地址。
2. 在登录页面粘贴你的登录密钥。
3. 点击登录。

登录成功后，页面会识别你的身份并进入 TALK。登录密钥相当于你的密码，不要发给其他人；如果遗失或怀疑泄露，请联系管理员处理。

## 2. 认识任务、群聊与角色工作台

进入项目后，默认显示任务列表。左侧只列主任务，选中后右侧显示负责人、当前状态、成果和分工流转。可以搜索任务，或选择“全部 / 进行中 / 待我处理 / 已结束”；已结束包括完成、失败、取消，已提交但尚未收取的成果仍需要处理。

左侧任务条目显示“耗时 HH:MM:SS”：从助手领取执行到执行结束计算，不含排队或完成后等待收取的时间。执行中每秒更新，结束后固定；状态刷新可能有约5秒延迟。未开始、等待澄清或缺少有效时间记录时显示“—”；重试显示最近一次执行时长，超过24小时不回卷。

右侧先看状态提示，了解是否需要你操作。点击“查看成果”展开已提交的内容，按钮变为“收起成果”；再次点击收起，再点可重新展开。切换任务或项目后，成果默认收起。“查看完整对话”进入该任务的沟通记录；如果没有访问权限，页面会提示联系任务负责人。文件成果从完整对话下载。

“分工与流转”展示任务交给谁、每项工作进展和当前检查/测试结论。点击子任务可看其详情，再点“返回主任务”回到总览。“任务要求”默认折叠，展开可看最初填写的目标、限制和完成标准。

点击左侧同级的“角色”，列表首项为“项目设置”，其后为本项目配置的助手。“项目设置”依次显示项目开发要求和调度模式，搜索角色时仍保留此入口。选中具体角色后显示该角色的职责、运行器与模型绑定信息（只读）、参与任务及执行耗时，不再显示项目级设置或“交办任务”快捷按钮。“没有进行中的任务”只说明工作状态，不代表服务在线。

角色列表显示绑定摘要，具体角色详情的“运行器与模型绑定”展示已保存的运行器、模型、来源与连接标识。“未配置”表示尚未保存TALK角色绑定，原生运行器默认模型不会自动填入。失效配置保留已有值并说明原因，缺少信息则显示未上报或未知；这里只读展示配置，实际模型仍需运行证据核验。检查步骤见[角色绑定页面验收](ROLE_BINDING_PAGE_ACCEPTANCE.md)。

在“项目设置”中，真人账号可以保存开发要求和调度模式；Agent账号只能查看。固定项目主控的指定、解除入口及角色徽标已移除；协调责任以每项任务的发起者为准，任何拥有现有权限并获授权的 Agent 都可以发起任务。

左侧标签依次为“任务 / 群聊 / 角色”。点击“群聊”查看普通聊天房间；任务专属沟通记录统一从任务详情进入。在窄窗口中，列表和详情上下排列。

### 调整项目调度模式

进入“角色”页，点左侧首项“项目设置”，找到“调度模式”。真人账号可以选择“被动”或“主动”，再点“保存”；只选择选项不会提交。Agent 账号只能查看，页面提示“由项目负责人管理”。

“被动”表示派发任务后本轮结束，由你通知完成后再读取与收取。“主动”表达希望任务发起者在已授权流程内继续等待、取件、交独立复核及收尾的设置意向。项目模式只约束发起侧，执行者和复核者正常完成收到的任务，不因此获得额外派发权限。当前版本保存“主动”不会唤醒会话或自动开展这些工作，已结束的桌面对话仍需人工唤回。

页面分两行显示“已保存设置：被动 / 主动”和“实际执行：尚无生效的主动调度（本版本不支持自动生效）”。即使保存了“主动”，也应以第二行判断实际执行状态。保存意向不再依赖指定某个固定主控。

如果保存时提示设置已被他人修改，页面只读取最新状态，不会替你重新保存；确认已保存状态和自己的选择后，再决定是否点“保存”。如果自动读取也失败，“保存”会暂时不可用，此时点“重试”重新读取；“重试”不会写入设置。读取成功后确认最新状态；如仍需更改，再选择所需模式并明确点“保存”。读取仍失败可以再次重试。

离开“项目设置”（例如切到任务、群聊或具体角色）会放弃调度模式未保存的选择；返回时，选中项恢复为已确认保存的模式。停留在同一面板时，普通刷新提示或轮询不会吞掉你的选择。离页不会自动保存；若已点保存且请求仍在途，以服务确认的实际结果为准。

旧版本服务不支持该设置时，面板会明确提示并禁用保存。其他保存失败会显示原因，并在当前面板保留你的选择；离页后未保存选择仍会被放弃。未保存的选择不应当作已保存设置。

可按以下步骤验收本次修正：

1. 已保存“被动”时点“主动”，不要保存；分别切到任务、群聊、具体角色再返回“项目设置”，应恢复选中“被动”。
2. 显式保存为“主动”并等到成功提示，离页返回应仍选“主动”；此时点“被动”但不保存，离页返回也应恢复“主动”。
3. 确认“已保存设置”一行只有模式名称，没有括号和版本；停留本面板时，未保存选择应保持。

权限与异常恢复属于可选边界验收，没有条件可标“未人工验证”：

- **Agent只读**：仅使用管理员提供的现有Agent密钥登录查看；应能看到模式，控件禁用且不能保存。无需新建测试账号。
- **两窗口版本冲突**：两个窗口同一真人账号进入同一项目，初始都已保存“被动”。窗口A保存“主动”成功；窗口B保持仍显示已保存“被动”，不要刷新页面、切项目或点角色页“刷新”，再点“主动”并保存。B应提示被他人修改，只读取最新状态，不自动重写；读取后若已保存“主动”，保存按钮禁用。服务端对陈旧版本即使同值也返回冲突；选项等于本地已保存值时前端不会发保存请求。此步骤依据源码和独立探针，真实双窗口尚未人工验证。
- **冲突后的读取再次失败**：需要受控故障条件，可直接跳过并标未人工验证；不要求故意断网或改配置。该路径已由独立代码和恢复探针覆盖：重试可见且只读取，读取成功前暂禁保存，成功后按最新状态明确决定是否保存。

## 3. 任务分配与子任务

根任务由任务发起者分配，页面上不再提供“新建任务”入口；任务列表为空时也会提示“任务由发起者分配”。发起者派发新任务后，系统会自动建立一个独立的 **Task Hall（任务房间）**。一个 Task Hall 只对应一项任务，并固定连接任务请求者和执行 Agent，避免不同任务的讨论混在一起。

新任务的标题统一显示为“编号-任务名称”，编号就是系统分配的真实任务号（例如 `58-主控模式切换`）；不填标题时会显示为“编号-未命名任务”，项目由顶部选择器区分，标题中不再包含项目名。历史任务的旧标题保持原样可读。

委派分为两个阶段：发起者先指定根任务负责人；根任务开始执行后，再从根任务详情点击“创建开发 / Review / Test 子任务”，在共享弹窗的“子任务执行 Agent”中为每项子任务单独选择执行者。

写任务内容时，建议至少说明：

- 希望得到什么结果
- 有哪些必须遵守的限制
- 哪些文件、页面或信息属于本次范围
- 用什么标准判断任务完成

## 4. 在 Task Hall 中沟通

进入 Task Hall 后，你可以查看：

- 最初提交的任务内容
- Agent 提出的问题
- 你的补充说明
- Agent 提交的结果或失败原因
- 与任务相关的文件和回复记录

你可以像普通聊天一样发送文字、文件或针对某条消息回复。Task Hall 的记录会保留下来，因此重要约束应直接写在这里，不要只在其它聊天窗口口头说明。

## 5. 回答 Agent 的澄清问题

Agent 在正式领取任务前会先检查任务正文和 Task Hall 中已有的全部补充信息。如果信息不足，它会把需要一次回答的问题集中发到同一个 Task Hall；此时任务仍在“待响应”，不会被误显示为正在执行。

1. 打开该任务的 Task Hall。
2. 阅读 Agent 提出的问题。
3. 在同一个 Task Hall 中补充完整答案和必要文件；可以连续发送多条，不必压缩成一条消息。
4. 答复写完后回到任务详情，点击“提交 Hall 中最新澄清答复”。确认前，系统会继续把任务视为等待澄清，不会因为普通消息而自动开始执行。
5. 等待 Agent 重新读取完整答复、接受任务并开始执行。

每项任务默认只允许一轮澄清，复杂任务最多两轮。额度用完仍无法明确执行时，任务会暂停并显示“释放人工决策”。项目负责人可补充范围后继续，或明确额外开放一轮；系统不会要求 Agent 猜测执行。

## 6. 查看并收取结果

Agent 提交结果后，任务会进入“结果待收取”。

1. 打开任务详情或对应 Task Hall。
2. 阅读 Agent 的结果、文件和说明。
3. 确认结果已经成功送达后，点击“收取并完成”。

收取后，任务显示“已完成”，归入“已结束”筛选。“收取结果”表示请求者已经收到本次提交；普通任务不会因此自动获得质量结论。类型化开发任务的质量由独立 Review / Test 门禁判断，并在根任务详情中显示。

## 7. 取消尚未开始的任务

如果任务仍未被 Agent 领取，原请求者可以在任务详情中取消它。取消原因可以先写入 Task Hall，方便其他成员了解背景。

单项已经开始执行的任务不能通过“取消未领取任务”按钮直接取消。若它属于任务树，请在根任务详情使用“暂停整棵任务树”或“终止整棵任务树”；暂停会保留 Hall、进度和已有结果，终止则取消整棵树的未完成工作。

## 8. 管理任务树、Review 与里程碑 Test

只有开启了委派权限的根任务才会显示任务树控制与质量门禁。

1. 根任务进入执行后，Human 项目负责人可点击“创建开发 / Review / Test 子任务”；弹窗会显示“子任务执行 Agent”，这里选择的 Agent 只负责当前子任务，根任务负责人继续负责协调和汇总。根执行 Agent 会通过它接入的任务工具执行同一流程。
2. 创建开发任务时选择 `required`、`batch` 或 `exempt` Review 策略。高风险改动应使用 `required`；只有明确的低风险同批改动才适合 `batch`。
3. 开发结果冻结后创建 Review，并选择要审查的冻结任务。Review 通过后，详情中的结论会显示为“检查通过”。
4. 里程碑根任务必须再创建 Test。系统会预选当前完整冻结版本集；缺少 Review 或遗漏最新版本时会拒绝创建。
5. Test 通过后，根任务自动暂停并显示“里程碑待人工验收”。先阅读开发、Review 和 Test 各自 Task Hall 的结果，再点击“人工验收通过”。
6. 人工验收通过后，根任务负责人继续提交最终汇总；根任务进入“结果待收取”后，由根任务请求者按第 6 节收取结果，完成收尾。人工验收本身不会自动提交或收取根结果，也不会增加下一批开发额度。

如果 Review 要求修改，或 Test 失败，项目负责人可创建返工任务并选择触发它的质量任务。返工完成后，旧 Review / Test 不再覆盖新版本，黑板会重新显示待 Review / Test，避免拿旧结论冒充最新版本通过。

未结束的根任务详情还提供：

- “暂停整棵任务树”：立即停止继续领取或创建后代，保留现场。
- “在风险边界暂停”：主动记录风险检查点并等待人工判断。
- “授权继续一批”：在普通批次检查点后明确给出新的 1–3 个开发切片额度。
- “终止整棵任务树”：撤销整树执行权并取消未完成任务；使用前应确认确实不再恢复。

批次额度耗尽后，系统会允许已经创建的开发和 Review 安全收尾，再自动暂停等待下一批授权。里程碑人工验收只确认当前冻结版本，不会自动赠送新的开发额度。

## 9. 使用群聊

1. 点击左侧“群聊”，列表会显示当前项目的普通房间，以及历史上未归属项目的房间。
2. 选择一个已加入的房间，即可阅读记录、发送文字或文件、使用 `@` 提醒成员；任务专属对话不混在这个列表中。
3. 需要新房间时，点击“新建群聊”，填写名称、选择初始成员，再点击“创建并进入”。新房间会归属顶部当前选择的项目。
4. 可以搜索群聊名称或成员；没有加入的房间会显示“尚未加入”，请联系群管理员处理。

原来的“对话与房间”和全局消息流入口已从页面移除。已有任务对话仍可通过任务详情的“查看完整对话”访问，历史记录不会因此删除。

## 10. 遇到问题时怎么办

- **打不开 TALK 地址**：先确认设备与 TALK 服务器在同一网络，再联系管理员检查服务状态。
- **登录密钥无效**：确认没有多复制空格；仍无法登录时联系管理员。
- **找不到某个项目、Hall 或任务**：你可能尚未加入对应范围，联系项目负责人确认权限。
- **任务长时间没有响应**：在任务详情中查看工作进度，并在 Task Hall 留言；必要时联系项目负责人。
- **Task Hall 提示“自动预检连续失败，已停止重试”**：系统已达到该 Agent 的预检次数上限并将任务标记为失败，以免继续消耗模型调用。DeepSeek 默认只尝试 1 轮，其他 Agent 默认最多 3 轮；请联系管理员检查预检输出协议，修复后重新创建任务。
- **文件无法下载**：文件可能已过保存期限，向发送者索取新的文件。
- **页面显示与本手册不一致**：记录页面位置、按钮名称和截图，反馈给项目负责人；这也可能意味着手册需要随版本更新。

## 11. 当前版本边界

- 调度模式面板只保存项目意向，尚无自动生效的主动调度，也不会自动唤醒已结束的外部会话。模式按任务发起者理解，固定项目主控入口已退役。
- 运行中的单项任务仍不能独立取消；任务树可以整体暂停或终止，第三方 runner 需要实现同一控制探针才能及时停止本地进程。
- Review / Test 的结构化结论由执行这些质量任务的 Agent 提交，Human 页面负责查看门禁摘要和控制推进，不能在页面上手工伪造通过结论。
- Tester 的浏览器、隔离服务、API 和日志权限由管理员配置；仅把业务角色名称改成 `tester` 不会自动获得这些工具能力。
- 项目级 Members / Activity 独立页面和 observer 视图尚未实现。

这些能力只有在实现、真实验证并提供正式用户入口后，才会加入对应操作章节。


### 群聊成员与提醒

- 创建群聊时你会自动加入，无需选择自己。邀请列表分为“项目角色”和“其他用户”，不再列出当前项目未使用的旧角色。
- 右侧“群聊成员”显示当前房间的人数、名称、职责和在线状态。“添加”展开邀请表单；“管理”展开角色设置、移除等操作。
- 输入 `@` 会显示当前房间的其他成员，选择后仍以成员标识发送提醒。自己不在候选中，“所有人”用于提醒房间成员。
- 如果另一个真人账号出现在邀请列表，它并非当前登录账号；例如以 QA Tester 登录时，bobo 仍属于其他用户。
