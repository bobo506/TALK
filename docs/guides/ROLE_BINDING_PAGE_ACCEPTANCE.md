1. 按 `Ctrl+F5` 重新加载 http://127.0.0.1:8000/，确认四处静态资源版本为 `20261010-adapter-closeout-c4`。

3. 同一指引须说明：并非所有终端都已有可用适配来源；当前入口可以生成计划，缺少来源或存在未知覆盖层时计划会 blocked，补齐并重新核验后再生成计划。
4. 选中 K2.8 角色（当前 `bound`）。指引须说明：以上只是已保存的配置值；改动配置后需要重新核验来源并生成新的收尾计划、再由受权 human 入口收尾，页面不会自动改动实际模型或权限；并显式否定“已绑定 = 运行器已验证 / 实际模型一致 / 在线 / 支持主动等待”。
5. 失效、不完整（partial）、运行器未登记/已退役、离册、禁用等状态：原有字段与状态照旧保留，指引要求先补齐对应适配来源或成员资格，再重新生成收尾计划；不得提示覆盖（overwrite）、重启已退役运行器或绕过人工确认。
6. 旧服务缺字段、状态未记录、未知枚举：继续诚实降级；指引按“确认该状态含义并重新核验”给出下一步，不冒充“未配置”，也不猜默认 runtime/model。
7. 切换角色、进入“项目设置”再回来：绑定面板与指引随选择切换；角色说明的未保存草稿不被重绘覆盖，焦点与草稿保持；绑定区（含指引）始终没有可编辑控件，也不产生按角色或写请求。
8. 缩窄窗口，确认新增指引段落可读、不撑破横向布局。

### 来源不足与输入边界

- 收尾指引是操作路径提示，不代替真实核验：先在对应终端确认运行器、模型与连接事实，再显式生成收尾计划（plan）。
- 计划来源不足或存在未知覆盖层时结果为 blocked；应先补齐来源并重新核验，再重新生成计划，不要用它覆盖或重启既有运行器。
- 页面只读：登记与收尾都在受信 human 凭据入口完成；页面不写绑定、不改实际模型或权限；绑定区不新增独立轮询，原有页面同步保持。
- 详细入口、凭据取得方式与完整命令见 [K28 执行器指南](KIMI_K28_EXECUTOR.md) 与下方“启动与登录”；产品文案刻意不含这些细节。
