# 发起者调度消费者指南（INITIATOR_MODE_CONSUMER）

> 2026-10-07由Codex发布：Kimi #180起草，DeepSeek #181独立A–F复核通过；原草稿/复核报告保留。本文为约定级指南，真实主动链路仍待I-4验收。
> 文档性质：**约定级**消费者纪律与提示词，不是代码合同。代码级边界 = 受控等待进入门禁 G1–G8（`bridges/talk_task_tools.py`）与服务端既有权限；本指南的一切纪律（重读资格、有限总预算、停止分类）当前由提示词约定承载，尚无代码强制。
> 正式合同与门禁定义见 [CONTROLLER_MODE_DESIGN](../spec/CONTROLLER_MODE_DESIGN.md) §3/§4/§7，实施顺序见 [INITIATOR_MODE_IMPLEMENTATION_PLAN](../spec/INITIATOR_MODE_IMPLEMENTATION_PLAN.md)。

## 0. 生效边界（先读，避免误判）

- 2026-10-07发布时当前项目实测状态：`requested_mode=passive`、`requested_version=6`，`effective_mode` 恒为 `null`（`effective_status=not_bound`）。**保存 active 只是模式意向**：不唤醒任何会话、不产生等待/调度/派发或任何授权、不表示真实主动链路已生效。
- 以下事项**都不等于**真实主动生效：保存了 active、源码复核通过、模板检查通过、MCP 目录/运行时加载核验通过、试派任务成功。真实主动链路验收（I-4）完成前，`effective_mode` 保持 `null/not_bound`，页面“实际执行”行不变。
- **默认协作仍是被动**：派发后本轮结束，由用户通知完成后再读取与收取。只有用户/决策方明确授权的主动流程才使用本指南的受控等待路径。
- 模式**只约束任务发起侧**。执行者与复核者**不读取模式、不依赖模式**：正常完成已接任务并交付；模式切换不取消在途任务、不重复收取、不扩大其派发权限、不自动开启下一片。

## 1. 核心概念：协调资格只看任务 created_by

- **唯一协调归属依据**是任务的 `created_by`：由服务端在创建时写入，请求体不可指定，无修改入口，创建即固定、不可变。
- 以下均**不是**协调资格，不能自证：`target_member_id`（执行者身份）、业务角色标签（business_role）、决策分级（decision_tier）、模型名、终端名、`TALK_MEMBER_ID` 环境变量、旧的固定项目主控指定（`controller_assignment`，已弃用的历史兼容字段）。
- 身份只能来自服务端按 API Key 反查（`caller_identity` / `GET /api/members/me`）；模型自称、会话标题、桌面 UI 都不能改变身份。
- 发起者身份只对“自己创建的任务”成立：同一成员可以在任务 A 是发起者、在任务 B 是执行者，互不推导。
- 项目主被动是统一设置但只约束发起侧：被动 = 派发后结束、通知后取件；主动 = 发起者在**已获本次授权的任务流程内**等待交付、读取结果、安排独立复核并收尾，每一步走既有工具与既有权限。

## 2. 启用前核验清单（逐项全过才可启动主动消费）

| # | 核验项 | 通过标准 | 不通过时 |
|---|---|---|---|
| 1 | 本次授权 | 用户/决策方明确授权本次主动跟进的具体任务与范围 | 不启动，按被动流程 |
| 2 | 身份 | `talk_list_agents` 实测 `caller_identity.member_id` 为本人且 `kind=agent` | 停止；human 凭据不作为 Agent 协调自证（G4） |
| 3 | 模式与版本 | 项目响应含 `controller_mode`/`controller_mode_version`，`requested_mode=active`，记录 `requested_version` | 缺字段=不支持（不猜 passive/active）；非 active 停止 |
| 4 | 任务归属 | 每个待跟进任务逐一核验：`project_id` 为本项目、`created_by` 为本人 | 任一不符整批停止，不跟进合法子集 |
| 5 | 预算齐备 | T/W/返回余量/消费者有限总预算/宿主外层预算均已核验并记录来源（见 §3） | **无明确有限总预算时不启动主动等待**；未知 T 不启用主动长等待 |
| 6 | 工具加载 | MCP 目录为九个工具，wait schema 含 `controlled_wait` 与 G1–G8 描述 | 重连加载后再核验；旧目录/旧进程不得当作已加载 |

任何一项在运行中发生变化（身份、模式、版本、任务归属、授权），**立即停止消费者**，按 §5 停止分类处理。

## 3. 等待预算边界（六项互相独立，分别核验、分别记录）

| 预算 | 含义 | 记录要求 | 当前已知事实 |
|---|---|---|---|
| **T** 客户端单次工具上限 | 宿主客户端对单次工具调用的真实上限 | 核验实际配置键、取值、单位、作用范围与重载方式；注明依据来自运行配置、模板还是用户实测 | DeepSeek 桌面 `toolCallTimeoutMs: 65000`（65 秒，配置事实）；Codex 当前项目实读配置 `tool_timeout_sec=660` 仅为前次配置读取，**真实长等待/连续阻塞能力仍未验收**；Kimi 模板 `toolTimeoutMs: 660000` 只是模板事实 |
| **W** 单次显式等待 | 每次 `talk_wait_tasks` 显式传入的 `timeout_seconds` | `W + 返回余量 ≤ T`，余量至少参考 5 秒；未知 T 不启用主动长等待，不把通用默认 600 秒套到所有终端 | DeepSeek 桌面 W=50（留 15 秒余量，已核事实）；Codex 当前项目 W=300 为用户现用值；其它终端按真实 T 定 |
| 返回余量 | 网络请求、序列化与客户端处理的余量 | 覆盖从等待返回到结果落盘的最坏路径 | DeepSeek 桌面 15 秒（已核）；参考下限 5 秒 |
| 执行者任务预算 | bridge 执行任务的超时 | 与等待预算**分别记录**，互不影响 | 现用 3600 秒；等待到期**不取消、不重派、不重启**执行者任务 |
| 消费者有限总预算 | 发起者本次主动流程允许消耗的累计等待总量 | 启动前明确给出有限值；每次续等前扣减并复核 | 提示词约定，尚无代码强制；**无明确有限总预算不启动主动等待** |
| 宿主外层交还控制预算 | 宿主外层工具（如 yield/wait）交还控制权的配额 | 与 T/W 分别核验；项目配置不能覆盖宿主限制 | 各宿主自行核验；连续阻塞能力未经验证不得宣称 |

**如实边界（不得弱化表述）**：受控等待是同步 stdio 阻塞，等待期间**同一条 MCP 连接上的其它工具调用排队**；客户端取消（notifications/cancelled）**不会立即终止程序侧等待**，等待仍跑到命中或超时截止；Windows 下客户端进程退出不保证带走 MCP 子进程；socket 单请求超时**不等于**任意慢响应的端到端硬截止。

## 4. 受控等待资格与输入规则（G1–G8 摘要）

`controlled_wait=true` 是显式 opt-in。**仅当**“已授权主动流程 + `kind=agent` + 本人 `created_by` + 同项目 + 最新 active 与版本核验”全部成立才可调用；门禁任一不满足直接报错，绝不静默降级为普通等待：

- G1 项目上下文可解析；G2 显式传入有限正数 `timeout_seconds`（bool/非数值/NaN/inf/0/负值拒绝，不采用 600 默认；超过 600 按既有上限 clamp 生效）；G3 Key 反查身份成功且响应合法；G4 human 凭据拒绝；G5 服务端返回模式字段（缺字段=不支持）；G6 `requested_mode=active`（用 G5 同一次响应判定）。
- G7 `task_ids`：**必须显式提供、非空数组，元素全部为严格正整数**——bool、浮点（含 1.0）、字符串、null、0、负整数**整批拒绝**（不 `int()` 转换、不截断、不静默丢非法项、不等待合法子集）；全部合法后按首次出现顺序稳定去重（重复不是错误）。
- G8 按去重顺序**逐唯一 ID 各发恰好一次**任务 GET，核验存在/对调用者可见/属于本项目/`created_by=调用者`；任一不符**整批拒绝**。404 措辞只说“不存在或对当前调用者不可见”，只回显调用者提交的 ID，不断言存在性、不泄露任务内容。
- 进入期所有 HTTP（身份 1 + 项目 1 + 逐任务 N，含失败尝试）计入同一 deadline 与 `query_stats.http_requests`。
- 运行期每 30 秒**只重读项目模式字段**（不再读取或比对旧主控指定）：模式值/版本变化或字段失效 → `mode_changed` 正常退出。正常退出枚举只有 `matched / timeout / mode_changed`；`api_error` 是错误路径（显式报错），不是正常退出。
- **`matched` 只表示任务状态命中，不是资格凭证**：每个后续动作前必须重新核验资格（见 §5）。
- 等待全程只读：不自动 collect/delegate、不改任务状态、不取消在途、不伪造 `effective_mode` 或调度互斥。

## 5. 有限状态推进顺序

```text
[授权确认 + §2 清单全过]
  -> 派发（既有权限）并记录真实任务号
  -> 受控等待 controlled_wait=true（G1–G8）
       |-- matched       -> 重读资格 -> 读交付 -> 派独立复核 -> 复核通过再核验 -> 收取 -> 汇报
       |-- timeout       -> 仅单次读到期：总预算未耗尽且资格仍满足 -> 重读资格后有限续等；否则停止
       |-- mode_changed  -> 停止消费者，转被动收尾
       |-- api_error     -> 显式报错路径：停止本轮主动等待并如实记录
       |-- 客户端取消     -> 如实记录；程序侧等待仍跑到截止（§3 边界）
       |-- 总预算耗尽     -> 停止消费者，不再发起新等待
  -> 任一时刻版本/资格/授权变化 -> 立即停止消费者
```

正常 `return_reason` 只有 `matched`、`timeout`、`mode_changed`；上图的 `api_error` 是错误路径分类，客户端取消是宿主状态，总预算耗尽是消费者停止决定，均不是新增的正常返回枚举。

- 每次后续动作（**读交付、派复核、收取、汇报**）前都重新 `talk_list_agents` 核对身份/模式/版本，并重新核对任务归属（`created_by` 为本人）；matched 不能免除这一步。
- 版本或资格变化后**停止消费者**：不取消、不重派、不干预执行者在途任务，等待到期也不重启执行者任务。
- timeout 只表示**本次单次读取到期**，不表示任务完成、也不表示失败；是否续等只看授权总预算与当前资格。
- API 错误、客户端取消、模式变化、总预算耗尽是**四种分别的停止原因**，分别记录，不得混为“任务完成”或“普通到期”。
- 不无限重试/轮询；连续阻塞能力未经验证的终端不宣称支持长等待。

## 6. 可直接复制的发起者消费者提示词

> 用法：把 `<...>` 占位符替换为本次实测值后，作为发起者会话内的消费者指令。模板本身不授予权限；授权、预算与资格仍按 §2/§3 逐项核验。

```text
你是本项目任务的发起者协调方（消费者）。本次主动跟进已获明确授权，授权范围为任务 <TASK_IDS>。
1. 先调用 talk_list_agents：确认 caller_identity.member_id 为本人（<MY_MEMBER_ID>）且 kind=agent，
   读取项目 <PROJECT_ID> 的 requested_mode 与 requested_version。模式不是 active、字段缺失或身份不符时，
   停止主动流程，按被动处理（派发后结束、通知后取件）。
2. 对 <TASK_IDS> 中每个任务调用 talk_get_task：核对 project_id=<PROJECT_ID> 且 created_by=<MY_MEMBER_ID>。
   任一不符即整批停止，不跟进他人任务；target/角色/模型名/旧主控指定都不是协调资格。
3. 确认预算并记录来源：客户端单次上限 T=<T 秒>，本次 W=<W 秒>，返回余量=<MARGIN 秒>
   （W+MARGIN<=T，MARGIN>=5），消费者有限总预算=<TOTAL_BUDGET 秒>。无明确总预算不得开始等待。
4. 调用 talk_wait_tasks(controlled_wait=true, project_id=<PROJECT_ID>, task_ids=<TASK_IDS>,
   timeout_seconds=<W>)。task_ids 必须是显式非空的严格正整数数组。
5. 按正常 return_reason 与错误/宿主状态分别处理：
   - matched：先重读身份/模式/版本与任务归属（matched 不是资格凭证），再用 talk_get_delivery
     读取完整交付摘要（合看同一响应的 preview 与 summary_text，不要只读 summary_text）。
   - timeout：仅本次读取到期；总预算未耗尽且资格仍满足时，重读资格后有限续等；否则停止。
   - mode_changed：停止消费者，按该正常返回原因如实记录，不当作任务完成。
   - api_error（错误路径）/客户端取消（宿主状态）/总预算耗尽（消费者决定）：分别停止并如实记录；这些不是新的正常 return_reason。
6. 需要复核时，由你（当前发起者）按最新项目开发要求创建独立复核任务，复核者与执行者不同；
   复核通过前不收取、不宣称完成。执行者与复核者不读取模式、不自行推进下一片。
7. 收取前再次核验资格；collect 只表示结果已收取，不等于验收。汇报时如实区分已验收/未验收项。
全程只读等待：不取消、不重派、不干预执行者在途任务；版本/资格/授权变化立即停止消费者。
```

## 7. 交付读取与收取纪律

- 最终结果消息应为完整的 `talk-delivery-1` **裸 JSON**（或仅套一层 ```` ```json ```` 围栏），不加开头/结尾说明文字；被截断的 JSON 不再合法，摘要会判 `invalid` 或 `unknown`。
- 合法摘要要**合看同一响应**的 `preview.blocked/unfinished/completed` 与 `summary_text`（验证证据、限制、下一步、变更文件、基线在 `summary_text`），不能只读 `summary_text` 下结论。
- `unknown`/`invalid` 时**不能**从 runner 状态 `succeeded` 猜业务结论；按稳定 `result_message_id` 与 `expect_sha256` 分页补读，遇 `stale_reference` 从 `offset=0` 重新获取，不拼接两份结果。
- 本地降级路径（MCP 摘要不可信时读本地交付包副本）：必须实际通过 `scripts/talk_workflow.py validate --expect-task-id <真实任务号>` 校验、核对与完整结果消息一致、并有独立证据，且**如实标识这是降级路径**；不改旧结果、不追改旧报告。
- `talk_collect_result` 只把 `submitted` 推进为 `completed`；**收取不等于验收**。独立复核通过、确认验收后再收取。
- 复核前暂停；原源码证据指纹（基线 SHA/HEAD）保留可查；正式 PROGRESS 由 Codex 维护，执行者不更新进度文档。
- 详细交付合同见 [TASK_WORKFLOW](TASK_WORKFLOW.md)（talk-delivery-1 schema、`talk_get_delivery` 三状态与补读规则）。

## 8. 复核派发纪律

- 新的复核任务由**当前发起者**创建（独立顶层任务、最小参数），并遵守**最新**项目开发要求的分工快照；已派发任务按原包执行。
- 复核者必须与被复核任务的执行者**不同**；复核者独立核对实际文本/源码依据，不只采信执行者结论。
- 执行者与复核者**不读取模式、不依赖模式**：正常完成已接任务并交付；模式变化不产生任何执行侧动作，也不自行推进下一片。
- 协调责任按具体任务 `created_by` 归属：发起者只跟进自己创建的任务，不接管他人任务的收尾。

## 9. 明确禁止

- 不把保存 active、源码/模板检查通过、MCP 加载通过或试派成功称为真实主动生效（见 §0）。
- 不冒用他人 Key、不跟进 `created_by` 非本人的任务；不用 target/角色/模型名/旧指定自证资格。
- 不把 `matched` 当作持续有效的资格凭证；不无总预算启动或无限续等；不跨终端套用 600 秒。
- 不取消、不重派、不干预执行者在途任务；不伪造 `effective_mode`、不虚构调度互斥或会话绑定。
- 不做全仓机械替换旧文；历史日期/实测记录/旧任务快照不追改。
