# 发起者主动跟进

2026-10-26实现。当前为开发/隔离验证版本，独立复核、当前宿主实际加载及人工验收分别登记在[进度](../PROGRESS.md)，本指南不代替这些验收。

项目设置中的主动/被动只约束任务发起者。主动会话持续跟进本次已授权的任务，读取交付，完成约定的核验、独立复核及返修后收取；遇人工澄清/里程碑、错误或预算耗尽就通知用户。被动保持派发后结束、由用户通知取件。切回被动停止后续跟进，不取消后台执行任务。

## 接入

使用持久的`talk_terminal_mcp.py`或`talk_send_mcp.py` stdio连接。前者十个任务工具，后者另含原延迟send共十一个。旧Pi直接工具及未接入该入口的客户端不据此获得主动能力；不修改其旧执行路径。

先按[终端预算要求](TERMINAL_MCP.md#终端适配必查工具超时与等待预算2026-10-06)核实当前客户端单次工具上限T，选择单次等待W、返回余量和有限总预算。必须满足`W + 余量 <= T`、余量至少5秒。W至多600秒、总预算至多86400秒；执行者自身24小时预算与此独立。配置数字只是调用方声明，不能代替实际宿主证据。

在MCP启动环境设置以下四个值，或为终端入口添加对应参数：

| 环境变量 | 终端参数 |
|---|---|
| `TALK_FOLLOWUP_CLIENT_TIMEOUT_SECONDS` | `--followup-client-timeout-seconds` |
| `TALK_FOLLOWUP_WAIT_SECONDS` | `--followup-wait-seconds` |
| `TALK_FOLLOWUP_TOTAL_SECONDS` | `--followup-total-seconds` |
| `TALK_FOLLOWUP_RETURN_MARGIN_SECONDS` | `--followup-return-margin-seconds` |

前三项必须齐备，余量默认15秒。比如**已核实T=65秒的客户端**可设置T65/W50/余量15/总预算1800；这是条件示例，不是其它终端的实测值。保留原身份Key及项目环境，重连MCP使新入口/配置生效；终端`--check`返回实际预算声明（未配置为null）。不要把Key写进命令行、交付或仓库。

用户保存主动后，在已授权任务中调用原`talk_delegate_task`，其回执会带`initiator_followup`与下一动作。被动派发不新增跟进。没有预算配置时不自动启用，调用方应按原被动流程结束并说明接入状态。单纯保存主动不唤回已结束的会话、不增加任何权限。

## 发起会话的流程

1. 派发前读最新角色、项目要求及真实身份。任务、复核、返修内容按本次分工确定，程序不替模型编造任务或扩大范围。
2. 收到`followup_id`后继续`talk_follow_tasks`的`next`。已有任务可显式`start`，同时提供项目、本人任务ID数组及预算对象。每批最多20个ID，逐一验证，任一不符整批停止；不扫描全项目。
3. `next_action=verify_delivery_before_collection`时读取同一响应的全部交付摘要。自由文本或无效报告仍为unknown/invalid；用原`talk_get_delivery`按稳定引用补读原文。按授权检查文件、测试或其它证据；需要独立复核时先暂停开发、冻结并派给复核者。复核/返修任务加入同一批次，不续总预算。原任务暂不收取，不阻碍收到复核交付。
4. 核验完成后调用`collect`，传回`next`给出的完整`reference`、实际`verification_summary`和非空`evidence_refs`。声明来自发起者，程序不把它伪装成独立审查证明；服务端会在同一写事务内复核模式、任务归属/控制及结果引用/正文。原人工收取入口不改变。
5. 持续处理本批次，直至需要用户、全部收取或停止。所有结果已收取只证明收取状态，不代表用户目标或人工验收自动通过，也不允许另开开发片。

单次到期会返回`wait_outcome=timeout`，剩余总预算允许时可续`next`。总预算按单调时钟计算，包含模型核验期间消耗的时间，不因续等或加复核任务重置。模式版本即使active→passive→active也会使旧跟进失效。连接断开后旧状态不重放；重新读取任务再显式开始。

## 停止与故障

`stop`只停止连接内跟进。新版stdio通道处理与等待请求ID严格匹配的`notifications/cancelled`和EOF；查询/ping不被长等待占用，第二个等待立即报`wait_in_progress`。取消不取消/重排/重启执行者任务。单次HTTP按当前剩余预算且至多5秒设置socket超时，但任意慢响应不提供硬实时退出承诺。

身份、模式版本、任务created_by/项目或根控制状态改变时停止。每次自动派发与收取还经过专用服务端事务守卫；旧服务缺新路由就报错，不回退到忽略条件的旧写操作。`outcome_unconfirmed`表示写入可能已提交，先读当前任务，禁止盲目重试或重派。报告文字只是待核材料，不会被程序执行成指令。

`talk_list_agents`仅为当前MCP连接的跟进附加局部effective状态。没有本连接证据仍为null/not_bound；页面不会把保存主动伪装成所有终端均已运行。当前宿主的正常命中/到期、取消、查询与实际T/W证据仍须分别留档。
