## 启动与入口

在项目根目录执行（服务已正常运行时不需重复启动）：

```powershell
python -m uvicorn server.main:app --host 127.0.0.1 --port 8000
```

打开 http://127.0.0.1:8000/ ，使用原有human账号的TALK API Key登录，选择项目并进入“角色”。不提供或生成新凭证；沿用当前已登录账号即可。若服务仍为旧后端，手动重启加载S1；若静态页面仍旧，按Ctrl+F5。资源版本为 `20260919-c1b-s2-owner`。开发时不建议开启 `--reload`。

右侧“项目开发要求”下方为“项目主控”，再下面是角色详情。角色列表和详情显示对应主控标记，以具体成员ID区分同名助手。

## 核心步骤

1. 未指定时选中一个角色，点击“设为项目主控”，确认项目面板、列表标记、角色详情同步。已指定只是职责配置，不代表在线或已经开始执行任务。
2. 选择另一个角色，其主控入口应置灰并说明需先解除；不能直接覆盖。
3. 点击“解除主控”，确认恢复未指定，再指定你最终希望担任主控的角色。刷新页面后指定仍保留；离线或重启不应自动撤销。
4. 在开发要求里输入未保存草稿，再指定/解除、切角色/任务/群聊并返回，确认草稿仍在；原任务/群聊操作正常，主控面板不残留到其它标签。
5. 在浏览器打开TALK，若窗口最大化，先点击右上角“还原”按钮，再拖动窗口左右边缘把窗口缩窄，确认面板不遮挡角色列表或参与任务表。这是浏览器窗口操作，不是TALK里的“拉伸”按钮。用Tab与回车指定/解除：指定成功移到解除入口，解除成功移到状态行，正常可继续键盘操作。

## 补充场景

- Agent账号只读，不出现可用写入入口；不要求为验收新建账号。
- 已有指定成员被禁用/移出名册时，刷新主控面板应保留其ID及不可用原因，human仍可解除。此场景涉及配置变更，可在测试项目验证；不要为基础验收删除正在使用的成员。
- 保存中主动点击搜索框、另一角色或切到任务/群聊，完成后不应将焦点拉回原主控；离开角色页的迟到响应不应重绘任务列表或改变其滚动位置。
- 有可控延迟时验证A→B→A再保存：旧请求回来不能提前结束新请求的“正在保存”状态，也不应额外发送写请求。当前请求成功/失败/冲突后都可结束；冲突只刷新提示，不自动替用户再次写入。

## 已知限制与验证边界

- 自动化为真实前端代码加DOM桩/隔离后端测试，不等于真实浏览器；窄屏与键盘手感以用户验收为准。
- 他处改变指定或名册后，可点击刷新读取最新状态；没有新增高频轮询。极端A→B→A往返且不再保存时，旧请求可能晚于返回时读取落库，需手动刷新获取最终值。
- 保存返回前点击页面空白处使焦点落body时，完成后可能恢复到主控区；切其它角色已修复。切角色后又切回原角色时按当前同角色上下文恢复。未实现全站焦点管理。
- 超过JavaScript安全整数的异常版本值会禁写并提示；不发送失真版本。旧服务缺字段明确不支持，不能当未指定。
- S1并发名册/禁用窗口仍保留：指定可能保存但立即显示不可用，仍可人工解除；不承诺提交瞬间候选有效性的原子保证。
