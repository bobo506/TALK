## 本次界面精简复验

1. 在原访问地址按 `Ctrl+F5`，进入TALK项目→“角色”，选中已有的“Kimi k2.8”，无需重复创建角色或取得新Key。
2. 列表保留运行器和模型摘要，去除独立成员ID行；每个角色仍只显示当前服务状态。搜索、角色选择和“项目设置”入口正常。
3. 详情保留成员ID、角色说明和参与任务；不再有运行器/模型整块属性、C4收尾指引或已完成配置的进度/三步卡，也没有返回自身的“查看角色”。
4. 详情服务区标题为“角色开关”；其下是“绑定重置”，按钮下方小字为“接入异常时修复本机配置，必要时更新接入凭据。”检查窄窗口下的换行、留白和可读性。
5. “绑定重置”保留原本机修复功能，不重新选择运行器或模型。确认框会说明必要时更新TALK凭据并使旧凭据失效；常规布局验收可点取消，不必真实执行。处理中/失败仍有简短提示和原有处理入口；Agent账号不出现可用重置。

## 先验页面与等待流程

1. 进入“角色”页，检查搜索旁“创建角色”和“全部启动”的位置、间距及窄窗口换行。搜索、选择角色和“项目设置”入口应正常。
2. 点击“创建角色”，应能选择已登记的Kimi Code，未核验/控制未知的提示应如实保留。选择Kimi后，模型目录为空且本项目有既有完整K2.8绑定时，点击“登记项目已有模型：K2.8 Preview”；实际模型登记后选中，再填写项目内未使用的新角色名称和可选介绍。已有模型直接复用，下架选项不会自动恢复；无可用既有模型时仍需管理员准备目录。其他未退役的已登记运行器也可创建，但受管启动资格另行判断。
3. 点击“保存并配置”，真实Kimi运行器ID不应再报422校验失败。宿主配置保持关闭时，应看到请求已保存和“等待开启宿主配置”；这时没有创建好的角色行，也没有启动服务。重复点击不会生成第二次提交。
4. 刷新页面或切换项目后返回，进度应来自当前项目；关闭弹窗仍能查看待创建请求。未创建成员前可点“取消创建”；角色已创建后不再提供这个操作。
5. 角色列表仍只显示当前服务状态；列表没有“启动/关闭”操作按钮。选择角色后在详情“角色开关”操作启停，详情不重复显示服务状态标签。创建弹窗仍可查看身份档案、本机接入配置和配置检查三步；已完成角色详情不再重复显示进度。
6. 在“项目设置”查看宿主配置。检查宿主名称输入、开启/更新/暂停按钮，以及真人可编辑、Agent只读的表现。宿主已开启且名称不变时，“更新宿主”应禁用。

## 完整配置闭环的准备与验收

2026-10-14实际配置记录：用户明确授权后，“Kimi k2.8”已有真实配置闭环，宿主`PC-202312301323`开启，该角色已进入列表。当前详情已按用户要求移除完成状态/三步卡，不显示它们是正常布局。私有路径已准备为`D:/claude-test/TALK-private/operator.key`与`D:/claude-test/TALK-private/keys`，无须再重复创建该角色。单请求worker按授权结束退出；以后新请求要自动处理仍需常驻worker。当前只证明身份/本机接入/配置检查，原生Kimi控制仍未核验，尚不能据此验收受管启动。

完整闭环需要server和worker运行在同一台电脑。页面可以来自局域网；仅点击“开启配置”不会启动worker。管理员需已有仓库外human operator Key文件、仓库外角色Key根，以及与页面设置相同的宿主名称；准备步骤见[worker指南](ROLE_REQUEST_WORKER.md)。本片发布没有替人类启用生产worker或部署凭据。

可沿用服务管理器的 `--provision-worker --provision-worker-apply`，或按指南运行独立worker。独立单轮处理示例（先替换实际宿主名和仓库外路径）：

```powershell
python -X utf8 scripts/role_provision_worker.py --project "prj_e8fe7066bbec" --host "<页面中保存的宿主名称>" --base-url "http://127.0.0.1:8000" --project-root "D:/claude-test/TALK" --key-root "<已准备的仓库外角色Key根>" --operator-key-file "<已有真人operator Key文件>" --enable --apply --once
```

1. 在项目设置开启配置，宿主名称与实际worker一致；使用新建的验收角色提交请求。
2. 在创建结果中观察等待领取、配置中和三步结果。宿主完成后角色应进入列表，创建弹窗可点“查看角色”关闭弹窗并选中对应详情；详情不再展示完成进度卡。配置成功不会自动启动服务，也不证明原生账号登录或实际模型能力通过。
3. 关闭弹窗、刷新页面，再打开角色详情，ID、说明与角色开关应可见；有关联请求和合法凭据代际的真人账号还可见绑定重置。未确认响应的保存会提示“核对并重试保存”，沿用原请求和载荷。
4. 失败时查看简短中文原因。普通失败或次数耗尽可点“继续配置”；本机接入确需修复时，在角色详情点击“绑定重置”，阅读小字说明与确认框后再确认。必要时会更新TALK凭据并使旧凭据失效，不更换运行器或模型；服务占用、版本冲突仍由服务端检查，页面不读取角色Key。
5. 两窗口操作冲突应提示刷新核对，不自动覆盖新版本。切换项目、账号或离开角色页后，旧响应不应写入当前页面。
