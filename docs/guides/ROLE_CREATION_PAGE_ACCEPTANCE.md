## 打开页面与账号

正在运行TALK时，打开原访问地址并按 `Ctrl+F5` 强制刷新。进入TALK项目的“角色”页；本地地址示例为 `http://127.0.0.1:8000`。六个本地静态资源版本应为 `20261013-role-creation`。

若服务未运行，在 `D:/claude-test/TALK` 中使用原环境启动：

```powershell
python -m uvicorn server.main:app --host 127.0.0.1 --port 8000 --reload
```

使用管理员已有的**真人账号**登录密钥；本片没有新增验收账号。Agent账号可以查看进度，不能创建、启用宿主或恢复角色。页面不要求填写或复制新角色的TALK Key。

## 先验页面与等待流程

1. 进入“角色”页，检查搜索旁“创建角色”和“全部启动”的位置、间距及窄窗口换行。搜索、选择角色和“项目设置”入口应正常。
2. 点击“创建角色”，依次选择运行器、模型，填写一个项目内未使用的角色名称和可选介绍。这里只列已适配的受管CLI运行器；没有可选项时需要管理员先准备目录，不会伪造默认选项。
3. 点击“保存并配置”。宿主配置保持关闭时，应看到请求已保存和“等待开启宿主配置”；这时没有创建好的角色行，也没有启动服务。重复点击不会生成第二次提交。
4. 刷新页面或切换项目后返回，进度应来自当前项目；关闭弹窗仍能查看待创建请求。未创建成员前可点“取消创建”；角色已创建后不再提供这个操作。
5. 角色列表仍只显示当前服务状态；列表没有“启动/关闭”操作按钮。选择角色后在详情操作启停，详情不重复显示服务状态标签。“配置进度”的三步是身份档案、本机接入配置和配置检查。
6. 在“项目设置”查看宿主配置。检查宿主名称输入、开启/更新/暂停按钮，以及真人可编辑、Agent只读的表现。宿主已开启且名称不变时，“更新宿主”应禁用。

## 完整配置闭环的准备与验收

完整闭环需要server和worker运行在同一台电脑。页面可以来自局域网；仅点击“开启配置”不会启动worker。管理员需已有仓库外human operator Key文件、仓库外角色Key根，以及与页面设置相同的宿主名称；准备步骤见[worker指南](ROLE_REQUEST_WORKER.md)。本片发布没有替人类启用生产worker或部署凭据。

可沿用服务管理器的 `--provision-worker --provision-worker-apply`，或按指南运行独立worker。独立单轮处理示例（先替换实际宿主名和仓库外路径）：

```powershell
python -X utf8 scripts/role_provision_worker.py --project "prj_e8fe7066bbec" --host "<页面中保存的宿主名称>" --base-url "http://127.0.0.1:8000" --project-root "D:/claude-test/TALK" --key-root "<已准备的仓库外角色Key根>" --operator-key-file "<已有真人operator Key文件>" --enable --apply --once
```

1. 在项目设置开启配置，宿主名称与实际worker一致；使用新建的验收角色提交请求。
2. 观察等待领取、配置中和三步结果。宿主完成后，角色应进入列表，详情显示“配置已完成”。配置成功不会自动启动服务，也不证明原生账号登录或实际模型能力通过。
3. 关闭弹窗、刷新页面，再打开角色详情，完成进度应继续可见；未确认响应的保存会提示“核对并重试保存”，沿用原请求和载荷。
4. 失败时查看有限中文原因。普通失败或次数耗尽可点“继续配置”；本机接入确需恢复时，在角色详情点击“恢复本机接入”并明确确认。服务占用、版本冲突等由服务端检查，页面不会自行轮换或读取角色Key。
5. 两窗口操作冲突应提示刷新核对，不自动覆盖新版本。切换项目、账号或离开角色页后，旧响应不应写入当前页面。
